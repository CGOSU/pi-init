# pi-init

`pi-init` 是 Pi 扩展：帮项目准备 AI Coding 协作说明，并提供角色切换、任务工作流和运行诊断命令。

## 能做什么

- 初始化项目的 `AGENTS.md`、`docs/` 项目记忆和 `.pi/role-models.json`。已有文件不会静默覆盖。
- 使用随 package 发布的 `pi-init-role-routing` Skill 提供通用职责规则；项目可配置角色及对应模型。
- 在 Pi 中切换职责、配置自动换角方式，并查看或管理任务工作流。
- 提供 `/blackbox` 运行诊断、`/large` 大型代码文件结构审阅，以及独立的 `pi-usage` 用量统计命令。

## 安装

```bash
pi install https://github.com/CGOSU/pi-init
```

安装后重启 Pi，在项目中运行 `/pi-init` 打开控制中心。也可以直接在本仓库试用：

```bash
pi --no-extensions -e ./extensions/index.ts
```

## 初始化项目

在 Pi 中运行 `/pi-init`，按提示选择快速初始化或高级初始化。也可以直接使用命令：

```text
/pi-init init [目录]       快速初始化；省略目录时使用当前目录
/pi-init advanced [目录]  高级初始化
```

初始化会生成协作说明、项目记忆和角色模型配置；遇到已有同名文件时会先请求确认。

## 常用命令

| 命令 | 用途 |
| --- | --- |
| `/pi-init` | 打开控制中心 |
| `/pi-init config [role-id\|workflow]` | 配置角色/模型，或配置工作流策略 |
| `/pi-init role <role-id>` | 切换到指定职责 |
| `/pi-init mode <auto\|confirm\|manual>` | 设置角色切换方式 |
| `/pi-init save` | 保存角色模型配置 |
| `/pi-init fresh` | 预览并确认交接后创建新会话；普通会话与工作流统一入口 |
| `/pi-init workflow status\|resume\|retry\|cancel\|fresh\|stop` | 查看或管理当前工作流；`workflow fresh` 保留为兼容入口 |
| `/pi-init diagnostics`、`/blackbox` | 打开运行诊断 |
| `/large` | 扫描大型代码文件的结构审阅候选 |

标准职责包括 `architect`（规划）、`developer-test`（实现与验证）和 `docs-commit`（文档与交付）；项目也可以配置自定义角色。角色切换方式为 `auto`（自动）、`confirm`（确认后切换）或 `manual`（手动切换）。

## 容量提醒与手动新会话

pi-init 直接使用宿主 `ctx.getContextUsage()` 的百分比，与状态栏同源；不再按消息字符数估算，也不额外添加输出或安全余量。低于 70% 时完全隐藏容量状态项（包括“容量”字样）；达到 70% 时显示百分比及“压力偏高”，超过 100% 时显示“超出窗口”，仍只提供软提醒。宿主用量不可用、窗口不匹配或虚拟模型下一物理路由未知时内部记为未知，状态栏不显示该项，不用字符数兜底。宿主指标也不代表请求一定超限，Pi 原生容量保护仍负责真实请求边界。

提醒不阻断请求或工作流、不主动压缩，也不额外请求模型摘要。同一 session/模型/窗口的容量提醒会去重；模型或窗口变化、压缩和新 session 后重新评估，启动、模型切换及压缩回调先清除观察结果；在下一次请求上下文事件或 Agent 收尾时重新读取宿主用量。

当同一 session 已报告过缓存使用，且单次缓存失配的估算额外成本达到 **$0.50** 时，Pi Init 会给出一次短交接建议；同一 session 最多提醒一次。提醒会显示本次额外成本及本 session 累计的缓存失配额外成本估算；状态栏示例：`Miss ≈$1.85`。累计金额仅包含插件成功观测并持久化的样本，不回溯历史；估算使用 Provider 用量和 Pi 的模型价格，不是账单金额。提醒不会自动准备快照、切换 session、暂停或停止任务；无可见 UI 时不发送也不累计。

普通会话无需先创建工作流：当前已确认的非 architect 执行角色可调用 `session_handoff` 准备短交接，显式填写目标、约束、完成项、待办、历史验证及其来源、未确认项和下一步；没有内容的数组也必须显式填写 `[]`。你可以先对当前 AI 说“请用 `session_handoff` 准备短交接，记录目标、约束、已完成/待办、历史验证及来源、未确认项和下一步”，等工具结果返回后仍在当前来源会话直接运行 `/pi-init fresh`，查看预览并确认；不要先执行 `/new`。该工具只保存有界历史背景，不创建 session、不验证当前事实、不授予执行权限。准备后若出现新输入、其他工具活动或 branch 变化，快照即失效；应在当前执行结束、现场稳定时准备。交接包超过 32 KiB 会完整拒绝、不截断；这是存储上限，不是 token 预算。

`/pi-init fresh` 会展示交接预览并等待用户明确确认，确认前重新核对来源 session、branch 和快照。新会话只接收所选历史背景及来源，不继承全部对话、旧执行身份或自动续跑；用户需在目标会话自行决定下一步。若安全门拒绝，提示会显示原因码及处置方向；不要绕过停止/恢复保护或未知工具结果。已完整配对的历史工具失败不会单独阻止普通交接，但缺失配对、未确认操作或嵌套回执不完整仍会拦截。这只表示工具调用已收敛，不代表失败操作成功或没有副作用；仍未确认的结果应写入交接的未确认项，且不要在目标重复执行。旧安装副本可能仍显示通用提示，需先更新并reload后才能看到新原因码。若迁移结果未知，来源保持冻结；先核对目标，不要从来源重复创建。目标已有待核对交接包时，可在目标运行 `/pi-init fresh` 重做核对。

未结束的托管工作流也使用 `/pi-init fresh`，但仍进入原有工作流交接路径并保留源冻结、停止/恢复和未知结果保护；`/pi-init workflow fresh` 继续兼容。70% 仍只是软提醒，不会因上下文占用或 cache miss 自动切换 session；手动交接也不保证 Provider cache hit 或费用下降，需真实 Provider 对照才能评估。

托管工作流的请求上下文视图不改写原 session：仅在任务、branch 和工具组边界可核实时，保留用户约束、失败/恢复/未知结果、完整工具调用与结果配对及当前任务交接后的活动内容；无法安全确认时保留完整输入。普通会话不做语义历史裁剪。实现取舍和验证边界见[设计决策](docs/decisions.md)及[会话记录](docs/session-log.md)。

## 可选：用量统计

安装 package 后可运行 `pi-usage` 查看 Pi 用量；指定时间范围或导出 SVG：

```bash
pi-usage 7d
pi-usage 2026-08-01 2026-08-25 --output usage.svg
```

`pi-usage --update` 可立即更新统计数据。详细诊断说明见[运行诊断文档](docs/runtime-diagnostics.md)。
