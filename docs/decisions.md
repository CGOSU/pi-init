# 设计决策

本文件记录已经确认且会影响后续实现的决定。临时想法和普通操作记录不写入此处。

## 记录格式

每项决策应包含日期、决定、原因和约束。如果后续改变决定，应注明被替代条目，而不是删除历史。

## 已确认决策

### 2026-09-04：通过独立状态项高亮实时缓存阶段

- 决定：保留 Pi 默认 Footer 的累计 `↑Input`、`↓Output`、`R`、`W`、`CH`、费用、上下文和模型信息，不调用 `ctx.ui.setFooter()`；新增独立 `pi-cache` 状态项展示当前模型请求的缓存阶段和本轮已确认结果。
- 原因：默认 Footer 负责累计用量，独立状态项可以在不复制或破坏宿主 Footer 逻辑的前提下表达实时阶段，并允许只高亮当前可观测动作。
- 显示语义：当前请求阶段使用主题 `accent` 加粗；Provider 已明确报告的 `cacheRead`/`cacheWrite` 正数使用主题 `success`；请求已发送但缓存 usage 尚未到达时显示“缓存判定中”。
- 约束：`message_end` 的最终 assistant usage 是本轮缓存结果的权威来源；只要最终值明确给出正数，才确认缓存读取、写入或读写。零值、普通 input token、缓存相关请求参数和 Provider 未报告的字段都不得推断为命中、写入或未命中；错误、中止、新会话和 reload 不得遗留活动高亮。
- 约束：监听 `before_provider_request`、`message_update`、`message_end` 和 `agent_settled` 生命周期；`message_update` 只在语义状态改变时刷新，避免逐 token 重绘；不轮询 DuckDB，不修改 `pi-usage`、数据库 schema、session usage 事实源或增加持久 custom entry。


### 2026-09-04：pi-usage 报表显示缓存更新时间

- 决定：查询汇总从 `usage_state.checked_ms` 暴露缓存最近刷新时间，并在报表标题下显示为本地 `YYYY-MM-DD HH:mm`；没有缓存状态时显示“未知”。
- 原因：普通查询可能直接读取未过期的 DuckDB 缓存，用户需要区分数据更新时间和本次命令执行时间。
- 约束：时间取缓存刷新完成时写入的 `checked_ms`，不使用 session 文件最新修改时间；不改变缓存过期判断和统计结果。


### 2026-09-02：上下文压缩后强制恢复职责边界

- 决定：所有 `session_compact` 都持久化 `pi-init-role-recovery` pending，不根据 `fromExtension` 分类来源，也不通过 `session_before_compact` 返回值追加恢复指令；恢复提示由每次 `context` 事件注入。`tool_call` 门禁只放行读取、`task_workflow(action="status")` 和 `switch_role`，阻断结果不终止 Agent。
- 原因：上下文压缩可能恢复任务内容却丢失模型对当前职责边界的显式确认；仅在 Skill 中提醒依赖模型记忆，无法阻止错误职责直接修改代码。所有来源统一上锁后，职责恢复只依赖明确交接结果，不依赖宿主来源标志。
- 约束：pi-init 已明确完成目标角色或任务交接时，续跑前追加 acknowledged 并直接继续，不要求重复切换；普通压缩和 reload/resume/fork/startup 加载已有上下文后重新 pending，new 或空会话不额外上锁。恢复门不猜测目标角色，失败、取消、模型不匹配或凭据失败都保持 pending；session_tree 只按目标 branch 的最新 recovery entry 恢复。

### 2026-09-01：edit 守卫只在错误路径增加诊断

- 决定：提示层只提供简短的唯一匹配、参数边界和非重叠预检；运行时包装 Pi 内置 `edit` definition，在校验前拒绝 read-shaped/malformed 参数，并将已知重复匹配/重叠错误转为可恢复诊断，保证无效或歧义调用不写文件。未知错误原样透传，不能保证模型永不产生非法调用。
- 原因：把降低错误率的提示职责与 fail-closed 的运行时安全职责分开，同时不重写 Pi 的 schema、精确匹配、重叠检测、renderer 或 mutation queue；合法成功路径不增加模型调用或工具提示 token。
- 约束：正常路径复用原生 definition 的 schema、description、prompt metadata 和 renderer；运行时诊断只覆盖稳定错误码。工作流提示中相关 policy 字符串按 JavaScript 文本字符统计，从实施前 2,034 字符压缩为 1,370 字符，减少 664 字符（32.6%）；完整规则唯一保留在公共 Skill。

### 2026-08-31：pi-usage 重算日期显示到分钟

- 决定：TTY 刷新摘要中的“重算日期”显示 session 文件的最新修改时间，格式为 `YYYY-MM-DD HH:mm`，原先的受影响自然日改标为“受影响日期”。
- 原因：重算日期应反映用量数据最新更新到何时，而不是本次扫描何时结束；复用 `session_files.modified_ms` 即可提供分钟级信息。
- 约束：只改变 TTY 进度摘要，不改变自然日统计边界、数据库事件时间或非 TTY 报表。

### 2026-08-31：状态栏指示点跟随 Agent 生命周期显示

- 决定：`pi-init` 状态栏指示点在 `agent_start` 到 `agent_settled` 期间使用主题 `accent` 高亮，其余时间使用主题 `muted` 灰色。
- 原因：直接使用 Pi 的 Agent 生命周期和 `ctx.isIdle()` 判断真实运行状态，避免增加独立状态同步逻辑。
- 约束：仅改变指示点颜色，不改变状态文本、工作流调度或 Agent 生命周期语义。

### 2026-08-31：采用会话内逻辑快照辅助精确编辑

- 决定：精确编辑首次缺少新鲜内容时先读取；每次调用 `edit` 前预检每个 `oldText` 的精确出现次数，只有全部恰好匹配 1 次、payload 只含 `path` 和 `edits` 且各 edits 不重叠才调用；成功 `edit` 后，在没有其他写入来源时复用已确定的替换结果作为当前上下文中的逻辑快照；`exact-text` 因 `oldText` 零匹配失败时定向重读并最多安全重试一次。
- 原因：减少同一会话连续编辑同一文件时的重复读取，同时保留精确唯一替换和冲突停止语义；逻辑快照只属于当前上下文，不声称底层工具提供缓存或自动推断修改意图。
- 约束：命令、工具、Git 操作或外部协作者可能写入目标文件后，逻辑快照立即失效并必须重读；参数结构错误、read 参数混入 edit、任一 oldText 多重匹配、edits 重叠、文件删除/重命名、编码问题、其他错误或第二次失败都必须停止。首版不引入完整文件内容缓存、hash/revision、文件监听、缓存文件、持久状态、配置项或运行时依赖。

### 2026-08-31：将通用执行和工具规则集中到公共 Skill

- 决定：任务执行流程、证据门控、`read`/`edit` 工具参数、角色交接、真实验证和工作流边界统一维护在随 package 发布的 `pi-init-role-routing` Skill；项目初始化生成的 `AGENTS.md` 只保留项目定位、环境、命令、知识库等项目特有规则，并引用该 Skill。
- 原因：这些规则跨项目通用，集中维护可避免模板复制、版本漂移和每个项目初始化文件的噪声；公共 Skill 更新后即可统一修正规则。
- 约束：Skill 按需加载，因此运行时 `task_workflow` 提示仍保留关键安全和验证边界；宿主环境快照、项目测试命令、项目记忆索引和团队 Git/知识库约定继续生成到 `AGENTS.md`。既有项目不会自动被重写，需重新初始化或手动迁移。

### 2026-08-30：采用新鲜证据门控的有限探索和简单任务 fast path

- 决定：规划、任务执行、重规划和 `subtask` 派发复用当前上下文中已注入或本会话已读取且仍新鲜的证据；只有位置、实现、影响或新鲜度不确定时才读取最小范围。探索按工具轮次控制：充分证据 0 轮、局部缺口 1 轮、未知位置或新符号/配置/调用链通常最多 2 轮。
- 决定：`workflowMode: "auto"` 下不超过 2 个任务继续走既有绕过路径，不创建持久工作流或调度角色，但按各任务指定角色切换后顺序执行，架构角色只负责规划；`shouldOrchestrateWorkflow` 的阈值和 `workflowMode`/状态协议保持不变。
- 原因：历史 30 次 `task_workflow(plan)` 的规划耗时中位数为 183.5 秒、工具轮次中位数为 7.5、工具结果约 98 KB、输出约 6,446 tokens；当前会话和 Context Packet 已经提供足够证据时，重复读取只增加规划延迟和 token 消耗。简单任务不需要持久工作流的隐藏续跑和状态开销，同时仍需保留角色边界与真实验证。
- 约束：安全、认证、公共 API、数据迁移、并发、删除或可能被其他协作者修改的工作区必须检查最新实现、调用方和测试；验证失败只定向读取报错位置及必要的一层调用方。低风险已有精确唯一 `oldText` 时可直接编辑，匹配失败后才最小读取。
- 约束：第一版不新增 `lazyRead` 配置、Context Packet 状态结构、文件哈希缓存或运行时依赖；仅复用当前上下文、新鲜度判断和既有精确 edit 保护。中英文模板保持同一语义，开发测试与文档角色不跨越各自文件边界。

### 2026-08-30：长工作流在非最终任务边界检查上下文压缩

- 决定：活动 `task_workflow` 中，每个仍有后续任务或需要重规划的非最终任务完成后，在 `agent_settled` 边界检查上下文；自动模式且使用率达到 50% 时压缩一次，再继续下一任务或重规划。
- 原因：长工作流的上下文会随任务累积，即使角色不变也需要在任务交接点提炼上下文；最终任务没有后续消费者，不增加无收益的压缩调用。
- 约束：低于阈值、未知上下文、`confirm`/`manual` 模式和最终任务跳过；角色切换与任务边界复用同一生命周期和 `Already compacted` 防重逻辑，压缩失败仍继续工作流。

### 2026-08-30：完成报告只显示失败验证

- 决定：中间任务和最终工作流完成报告只渲染验证数组中带明确失败语义的条目；成功条目不显示，没有失败条目时省略验证行。
- 原因：完成报告用于快速发现需要处理的问题，成功验证不应淹没失败信息。
- 约束：完整 verification 数组仍按原协议持久化；报告层只基于文本中的明确失败标记筛选，不改变提交校验、状态机或 local/subtask 数据路径。

### 2026-08-30：工作流完成报告只保留必要结果

- 决定：中间任务完成时只输出当前任务的摘要、实现原因、耗时和验证；最终工作流完成报告只输出目标、进度、最终任务结果、整体时间和最终任务验证，不重新列出前序任务。验证改为单行展示，完成报告不再渲染灰色 bullet 辅助项，也不再追加完整工作流状态。
- 原因：任务报告和最终工作流报告同时展示时，前序摘要、验证和状态字段会重复出现；灰色列表项只降低信息密度，没有增加交付判断依据。最终任务已经代表最后一个完成边界，整体报告无需再次复制所有历史任务。
- 约束：工作流状态仍完整持久化，验证事实不得删除；`task_workflow.complete` 必须由执行角色提供 `implementationRationale`，说明关键实现取舍，避免报告层猜测原因。local 和 subtask 完成路径使用相同报告口径，旧状态缺少该字段时仍可读取。

### 2026-08-30：职责语义迁移到 package 公共 Skill

- 决定：由随 `pi-init` package 发布的 `skills/pi-init-role-routing/` 维护角色语义、路由、职责边界和通用工作流规则；项目不再生成 `.pi/skills/<slug>/SKILL.md`，项目 `.pi/role-models.json` 的 `roleModels` 映射成为启用角色和模型选择的唯一项目级来源。
- 原因：避免每个项目复制一份职责规则并与 package 版本漂移，同时允许项目通过动态角色 ID 配置模型，而不引入运行时角色注册表。
- 约束：公共 Skill 不写入具体 provider、model 或 thinkingLevel；新增角色需要在 `roleModels` 中配置角色 ID并在公共 Skill package 中提供对应 `roles/<role-id>.md`。旧版顶层角色字段继续自动读取，只有显式 `/pi-init save` 才迁移到 `schemaVersion: 2`；旧项目 Skill 和用户自定义 Skill 不自动删除。
- 替代：替代 2026-08-04“保留 pi-init 项目级 Skill 作为默认产物”的当前实现决定；历史背景保留，但新脚手架和 package 发布规则以本条为准。

### 2026-08-30：职责边界遇到跨类工作时自动切换

- 决定：开发测试工程师只负责代码、测试和验证，不写文档；文档与收尾工程师只负责文档、版本和交付收尾，不写代码。两者遇到疑问、困惑不解或需求分析时切换到架构师；开发测试工程师遇到文档修改切换到文档与收尾工程师，文档与收尾工程师遇到代码修改切换到开发测试工程师。
- 原因：避免单一职责在不擅长或不被授权的交付范围内继续工作，确保需求判断由架构师统一处理，代码和文档分别由对应职责完成。
- 约束：职责交接必须通过实际角色切换，不得只改变输出口吻；简单任务仍选择最少职责，不为没有跨类工作的任务额外切换。

### 2026-08-30：TUI 菜单中的 Esc 用于返回上一级

- 决定：通用 TUI 菜单、初始化文本输入和角色模型搜索将 Esc 解析为内部返回结果；高级初始化按填写步骤回到上一个属性并保留已输入内容，第一步才返回上级菜单；Ctrl+C 仍保持取消语义，显式选择“取消”也不变。
- 原因：Esc 是层级导航的常用按键，不应在嵌套配置菜单中显示“已取消”或误进入取消分支；高级初始化需要允许用户逐步回退修正前一项；显式取消仍保留给需要放弃当前流程的场景。
- 约束：只改变 TUI 菜单/文本输入导航和调用方分支，不修改配置或工作流数据；RPC 模式继续使用原生输入，工作流状态弹窗仍使用 Esc 关闭。

### 2026-08-30：高级初始化确认和调用边界沿用 MENU_BACK

- 决定：高级初始化的 TUI 最终确认使用现有菜单组件区分“确认生成”“取消初始化”和 Esc 返回；Esc 回到角色模型步骤并复用草稿，首个项目名称输入的 MENU_BACK 由控制中心消费后重新显示控制中心，直接 `/pi-init advanced` 则传播给调用方返回编辑器。
- 原因：确认阶段同样属于高级向导层级，不能把 Esc 误报为取消；控制中心需要保留父菜单上下文，而直接命令没有父菜单，复用同一哨兵即可表达两种边界。
- 约束：Ctrl+C 和显式“取消”继续取消整个初始化；快速初始化和非 TUI 继续使用原有确认行为；不引入新的向导框架或依赖，已填写的文本、属性和自定义角色模型选择必须在回退后保留。

### 2026-08-26：pi-usage 按稳定 entry 身份去重 fork 历史

- 决定：usage、speed 和 activity 事件使用 Pi entry id 作为跨 session 文件稳定 key；无 id 的旧 entry 使用包含行号和完整 JSON 的 SHA-256 legacy key。报表读取按 key 选择唯一事件，session 按去重后 usage 的 canonical source_file 计数。
- 原因：Pi fork 会复制历史 JSONL entry，按源文件和行号累计会重复计算 token、费用、TPS、活动时长和 session；只在导入时去重无法覆盖已有派生数据，读取边界去重能保持事实源不变。
- 约束：fork 后新生成且 id 不同的 entry 仍计入；Total 继续为 input + output + cacheRead + cacheWrite，Cache Read 仍属于累计用量；不得修改 session JSONL 或引入额外依赖。

### 2026-08-26：pi-usage schema v3 首次升级事务化重建

- 决定：entry key 变化触发 schema v3 全量重建，事务内清理 usage/activity/speed、duration summary 和 session checkpoint，再从 JSONL 重建并写入新 schema；移除旧的只回填 speed_events 迁移。
- 原因：旧缓存使用源文件行号，无法可靠转换为跨文件逻辑 key；全量重建是最小且确定的迁移路径，失败可回滚，JSONL 继续作为只读事实源。
- 约束：首次升级会重新扫描所有 session，完成后恢复增量 checkpoint；无变化的后续刷新仍走现有增量路径。
- 替代：替代下方 2026-08-13“DuckDB schema 升级只回填新增 speed_events”的迁移决定。

### 2026-08-25：pi-usage 使用简洁自然日范围语法

- 决定：保留无参数和单个 `YYYY-MM-DD` 的兼容行为，新增 `yesterday`、`Nd`、`YYYY-MM` 和两个 `YYYY-MM-DD` 位置参数；`Nd` 包含今天，显式日期范围首尾均包含。
- 原因：位置参数比 `--from/--to` 更短，同时覆盖常用快捷范围和精确范围，不引入多套等价别名。
- 约束：日期按系统本地自然日解析；跨日用量、费用和调用次数按日期范围聚合，session 按源文件去重，时长合计已有逐日汇总；不修改 DuckDB schema。

### 2026-08-25：同一任务期间连续方向输入合并为一个 revision

- 决定：活动工作流同一任务执行期间收到的连续普通 `interactive`/`rpc` 输入，按到达顺序合并到同一个 `pendingRevision` 和审计 `revision` 的 `direction` 文本，保留首个 `revisionId`、请求时间和任务边界；当前任务完成后才进入 `replanning`，架构师收到完整合并指令后才能应用新计划。
- 原因：持续输入应表达同一轮方向调整，忽略后续指令会丢失用户意图，逐条创建 revision 又会造成多个待处理边界和重复重规划。
- 约束：合并使用换行连接的纯文本，不新增状态版本或配置；新计划应用前不启动旧后续任务，local/subtask、取消、重试和历史单字符串 `direction` 状态保持兼容；斜杠命令不进入合并路径。

- 决定：只有最后一个任务完成并使工作流进入 `completed` 时，才输出工作流整体完成报告；报告标题和核心摘要使用冻结的 `state.plan.summary`，并汇总全部任务、验证结果、冻结时间、整体实际开始/结束时间和总耗时。中间任务继续输出任务级完成报告。
- 原因：用户需要区分单个任务交付与整个架构规划的最终交付，避免把最后任务描述或任务耗时误报成工作流整体结果。
- 约束：整体耗时从首个任务实际开始执行到最后任务完成，不计入规划、审阅或调度等待；工作流级时间戳持久化并兼容旧状态回退；local 与 `subagents` 必须使用相同报告格式和现有醒目 TUI 样式；无有效时间边界不得伪造耗时。

### 2026-08-14：工作流完成结果必须保留完整报告

- 决定：`task_workflow complete` 的工具结果渲染器优先显示返回内容中的完整任务完成报告，而不是用工作流进度摘要覆盖它。
- 原因：完成结果本身包含任务摘要、开始/结束时间、总耗时和验证结果；只显示进度会让用户误以为这些信息没有生成。
- 约束：仅调整结果展示，不改变工作流状态机、完成时间戳、session 持久化或普通执行报告语义。

### 2026-08-14：补充非工作流 Agent 执行时间报告

- 决定：对未进入活动 `task_workflow` 的外部 `interactive`/`rpc` 输入，记录一次普通 Agent 执行的首次 `agent_start`、最终 `agent_settled` 和总耗时，并通过不进入 LLM 上下文的 `pi-init-run-timing` session custom entry 在 TUI 展示来源、开始时间、结束时间、总耗时和计时口径。
- 原因：工作流任务已有结构化完成报告，但 `workflowMode: "auto"` 绕过编排的普通执行缺少可见时间信息；普通执行报告可以补充运行时事实，同时不冒充业务任务完成。
- 约束：同一次执行的重复低层 `agent_start` 不重置首次开始时间；活动工作流、subagents 和扩展隐藏续跑不得生成普通报告；reload、会话切换或中断只丢弃未完成的内存计时，不补造结束时间；无效或倒退时间戳不生成耗时。

### 2026-08-14：工作流终态后恢复底部状态摘要

- 决定：工作流进入 `completed` 或 `cancelled` 后，底部 `pi-init` 状态栏显示初始的策略、执行器和“无活动工作流”摘要；控制中心和 `status` 仍保留终态工作流状态供查看。
- 原因：终态工作流不再是当前活动任务，底部状态应反映可继续操作的当前状态，避免残留“已完成/已取消”造成误解。
- 约束：不清除内存或 session 中的终态状态，不影响完成报告、状态查询和历史恢复。

### 2026-08-14：在 Agent 规则中约束 read/edit 工具调用

- 决定：项目及生成模板的 `AGENTS.md` 明确区分 `read` 与 `edit` 参数；编辑前必须重读并直接复制 `oldText`，匹配失败后必须重新读取，不得重复相同替换或使用模糊匹配。
- 原因：减少把 `offset`/`limit` 误传给 `edit`，以及手动改写引号、缩进和换行导致的精确替换失败。
- 约束：继续保留精确字符串替换和修改后 diff 检查，不通过放宽匹配规则换取表面成功。

### 2026-08-14：任务完成时输出基于状态机时间戳的完成报告

- 决定：每个工作流任务进入 `in_progress` 时记录 `startedAt`，完成时记录 `completedAt`；本地完成和 subagents 完成路径都输出统一的任务完成报告，包含任务信息、角色、时间、总耗时、摘要和验证结果。
- 原因：用户需要在任务结束时直接了解交付内容和实际耗时，统一 formatter 可避免不同执行器的输出字段漂移。
- 约束：`startedAt` 在任务实际派发给本地模型或子代理时记录，`completedAt` 在完成时记录；总耗时只使用这两个任务自身时间计算。不得使用模型启动、工作流创建或子代理可选生命周期时间伪造；旧状态的过时开始时间在首次实际派发时刷新。

- 约束：子代理只能在共享工作区执行，不自动创建 worktree、并行、合并、提交或推送；结果必须严格符合 `pi-init/task-result@1`，异常结果、RPC/扩展缺失和生命周期失败安全阻塞任务；任务创建时持久化 executor，reload 后不自动重生已绑定的非终态代理，取消/阻塞仅发送 stop 请求而不伪造完成。

- 约束：按 `process.platform` 选择 `.cmd` 或 POSIX shell 启动器；找不到 `pi` 时必须安全跳过并提示手动安装，不得阻断 package 更新；npm 禁用 lifecycle scripts 时仍需保留手动安装路径。

- 约束：通过 `1.0.4` 版本升级降低旧安装残留概率，不添加 silently fallback；`workflowEnabled` 兼容和既有工作流收尾行为不变。

### 2026-08-13：用 pi-token-speed 自定义 session 采样计算模型平均 TPS

- 原因：默认路径不需要重复输入已存在的项目元数据，也不应要求用户手动执行 `/reload` 才能加载新 Skill。
- 约束：高级初始化仍允许覆盖推断值；无法读取元数据时回退到目录名和空白可选字段；目标是其他目录时不自动切换当前会话资源。

### 2026-08-06：TUI 配置使用 Pi 原生主题组件和即时搜索

- 决定：控制中心使用 `DynamicBorder`、`SelectList`、`Input` 和当前主题色；TUI 模型选择在同一界面实时筛选，结果默认折叠并仅在展开时显示详细指标。
- 原因：复用 Pi 已有 TUI 能力可以改善层级和可读性，不引入新的 UI 框架或自定义主题系统。
- 约束：RPC 模式保留 `ctx.ui.select/input` 降级路径；模型搜索仍受当前模型范围和凭据限制。

### 2026-08-06：控制中心优先展示状态和摘要而不是完整细节

- 决定：`/pi-init` TUI 菜单显示模式、职责、当前模型的状态卡片；菜单项按初始化和职责分组并使用图标；初始化通知默认只显示文件数量和冲突摘要，完整文件列表保留在工具展开结果中。
- 原因：状态栏和通知中的长路径、完整文件列表会挤压选择区域；用户需要先做选择，再按需查看细节。
- 约束：状态信息必须随实际当前模型和推理级别更新；窄终端由 Pi 的 Text/SelectList 自动换行和截断，不增加独立响应式布局系统。

### 2026-08-06：并行子代理采用受限并发和可量化性能指标

- 决定：`parallel_develop` 默认最多同时运行 2 个 worker，最多接受 4 个任务；高频模型输出按 250ms 节流，工具和阶段状态仍即时上报。
- 原因：实际模型请求远慢于 worktree 创建，盲目并发会增加 provider 限流、长尾和集成等待；阶段指标用于区分模型耗时与本地编排耗时。
- 约束：保留独立 Pi 进程和隔离 worktree；仅在任务真正独立、契约冻结且足够大时使用并行，小任务或共享 DOM/API/测试契约的任务仍由单 worker 处理。

### 2026-08-06：并行子代理采用事件流和分级故障接管

- 决定：并行 worker 使用 Pi JSON 事件流，由主扩展实时更新每个任务的状态、当前工具、耗时和最后活动；基础设施错误最多自动重试一次，代码/测试错误交由主开发测试工程师接管，架构或合并冲突交由架构师处理。
- 原因：一次性等待子进程结束会让主界面长期显示 working，错误也无法区分责任人；事件流能提供进度，分级策略能避免盲目重试代码错误。
- 约束：失败任务的隔离 worktree、prompt 和 stdout/stderr 日志必须保留；只有全部任务成功且主工作区未变化时才自动合并和清理。

### 2026-08-06：自动跨角色切换在大上下文时压缩

- 决定：仅在 `auto` 模式发生真实跨角色、且切换前上下文使用率达到 50% 时，于当前回合结束后触发一次定制压缩；压缩成功后发送隐藏续跑消息继续当前任务。
- 原因：角色边界是自然的上下文交接点，大上下文需要先提炼目标、决策、进度、文件、验证结果和下一步；低于阈值或非自动模式不应增加额外模型调用。
- 约束：首次选角、同角色重复切换、未知上下文、`confirm` 和 `manual` 均跳过；压缩失败不回滚已完成的模型切换，也不阻断后续工作。

### 2026-08-06：并行 worker 按目标平台处理 CLI、路径和进程

- 决定：Windows 的 Node/Bun 备用入口通过 `cmd.exe` 加转义参数启动 `pi.cmd`；POSIX worker 使用独立进程组，Windows 使用 `taskkill /t /f` 终止子进程树；文件范围比较读取 Git `core.ignorecase`。
- 原因：Node `spawn(..., { shell: false })` 不能直接启动 Windows `.cmd`，大小写敏感性由实际文件系统和 Git 配置决定，单独杀父进程会遗留工具子进程。
- 约束：不引入新的运行时依赖；三平台回归由 GitHub Actions 矩阵执行，当前本地只完成 Windows 验证。

### 2026-08-06：会话恢复时只恢复唯一匹配的角色

- 决定：`session_start` 根据当前 provider/model 和实际推理强度恢复角色；多个角色配置相同或无法匹配时保持未知，不猜测角色。
- 原因：角色状态原先只存在扩展内存中，reload、resume 或次日重新打开会丢失，导致第一次真实跨角色无法触发上下文压缩。
- 约束：恢复只识别身份，不主动覆盖用户当前模型或推理强度；手动改过模型/推理强度时继续视为未知角色。

### 2026-08-09：用事件间隔估算 pi-usage 使用时长

- 决定：增加 `duration_summaries`，记录指定日期的活跃时长、模型等待时长和 session 跨度；活跃事件间隔不超过 5 分钟才累计，模型等待间隔最多累计 30 分钟。
- 原因：当前 Pi session JSONL 没有统一的模型调用开始/结束事件，只能基于带时间戳的消息和工具事件进行可解释的近似估算。
- 约束：模型等待时长不是精确的 API 延迟，也不代表用户实际操作时间；session 跨度仅作参考。

### 2026-08-09：pi-usage 默认日期范围从本地午夜开始

- 决定：未指定日期时，查询和更新范围从本地当天 `00:00` 开始，到下一天本地 `00:00` 结束。
- 原因：从当前时刻开始会漏掉当天较早的 Git commit，且与按 entry 本地日期筛选的 usage/activity 数据不一致。

### 2026-08-09：pi-usage 普通查询使用一小时自动检查缓存

- 决定：普通 `pi-usage` 查询仅在首次查询、距上次检查至少一小时或跨自然日时执行 session 增量检查；`--update` 始终强制检查。
- 原因：避免每次查看都扫描文件，同时避免用户忘记更新导致数据长期停留在旧快照。
- 约束：DuckDB 的 `usage_state` 保存全局检查时间和日期；文件变化后按文件大小/修改时间增量导入，受影响日期的派生汇总一并刷新。

### 2026-08-09：pi-usage 报告统一使用表格和终端颜色

- 决定：将 session 数量、模型用量、时长和 Git 变化统一输出为带边框的对齐表格；交互终端为表头、分隔线和 Total 行增加 ANSI 颜色。
- 原因：比混合的行内文本更容易扫描和比较，同时保留非 TTY 和 `NO_COLOR=1` 下的纯文本输出。

### 2026-08-10：pi-usage 移除 Git 展示并增加模型用量图表

- 决定：`pi-usage` 不再扫描或展示 Git 代码变化；报告增加按模型总 token 缩放的 Unicode 柱状图，并在 Overview 显示缓存占比。
- 原因：Git 变化与模型用量没有直接归因关系，移除无关统计可缩短更新路径；柱状图和缓存占比让 token 使用情况更易比较。
- 约束：缓存占比固定按 `(cacheRead + cacheWrite) / totalTokens` 计算并显示为百分比；柱状图以当天模型总 token 为量纲，非 TTY 和 `NO_COLOR=1` 保持纯文本。

### 2026-08-09：角色切换压缩等待 agent_settled

- 决定：自动角色切换的定制压缩只在 Pi 的 `agent_settled` 事件中启动，不再使用 `turn_end`。
- 原因：`turn_end` 时 agent run 仍可能处于活动状态，而 `ctx.compact()` 会先 abort 当前 agent；`agent_settled` 已等待自动重试、自动压缩和队列续跑完成，避免生命周期竞争。
- 约束：仍保留待压缩状态，压缩成功后才注入隐藏续跑消息；压缩失败不回滚已完成的模型切换。

### 2026-08-09：用 DuckDB 汇总跨 session 用量和 Git 代码变化

- 决定：增加 `pi-usage [YYYY-MM-DD] [--db <path>]`，将 Pi JSONL 中的 usage 事件导入 DuckDB，按模型汇总 input、output、cache token、调用次数和费用；工具内部摘要单独归为 `Tools/summaries`。
- 决定：从 session 的 `cwd` 关联 Git 仓库，额外统计指定日期的 commit 变化和当前已跟踪文件的未提交变化；未提交变化只作仓库级指标，不归因到模型。
- 原因：DuckDB 适合本地分析且不需要独立数据库服务；JSONL 仍是事实来源，默认命令只查询数据库，`--update` 只重读新增或文件大小/修改时间变化的 JSONL 文件。
- 约束：增量更新通过 `session_files` 保存文件大小和修改时间；变化文件会删除后重导其 usage/activity 事件，删除的 session 文件也会同步清理。
- 约束：默认数据库为 `~/.pi/agent/pi-usage.duckdb`；若项目或用户运行时没有 DuckDB，首次执行会安装固定版本到 `~/.pi/agent/pi-usage-runtime`；支持 `PI_CODING_AGENT_DIR` 和 `PI_CODING_AGENT_SESSION_DIR` 覆盖位置。

### 2026-08-06：生成的 Skill 使用精确字符串替换规则

- 决定：中英文项目 Skill 都要求先读取最新文件，并使用唯一匹配的 `oldText` → `newText` 替换；匹配失败或不唯一时停止修改。
- 原因：复用 Claude Code Edit 类工具的精确修改语义，避免模糊定位和整文件重写带来的误改。
- 约束：使用最小唯一上下文；同一文件的多个不相邻改动必须是一次编辑中的互不重叠替换，完成后检查实际 diff。

### 2026-08-06：离线启动器与扩展更新器分离

- 决定：将 `pi-fast` 和 `pi-update` 作为仓库内跨平台脚本维护；前者只对子进程设置 `PI_OFFLINE=1`，后者只对子进程清除该变量并执行扩展更新。
- 原因：启动不应因网络检查阻塞 UI，但升级仍应显式可用；把脚本放入仓库可在换电脑时重新安装。
- 约束：启动器不在启动阶段联网；Windows 安装到 Pi 所在 npm bin 目录，POSIX 无写权限时安装到用户 bin 并提示 PATH；更新后需 `/reload` 或重启 Pi。

### 2026-08-12：移除无用的辅助启动器

- 决定：删除 `pi-fast` 和 `pi-update` 的跨平台脚本、安装器复制逻辑及文档和测试引用，仅保留 `pi-usage`。
- 原因：这两个命令不再有实际使用价值，减少发布包和安装器维护负担。
