# 设计决策

本文件记录已经确认且会影响后续实现的决定。临时想法和普通操作记录不写入此处。

## 记录格式

每项决策应包含日期、决定、原因和约束。如果后续改变决定，应注明被替代条目，而不是删除历史。

## 已确认决策

### 2026-08-15：工作流报告时间跟随系统本地时区

- 决定：报告开始/结束时间使用运行 Pi 的系统本地时区，并以 `YYYY-MM-DD HH:mm:ss±HH:MM` 显示；持久化仍保存 Unix 时间戳。
- 原因：固定 UTC+8 只适用于特定部署区域；系统本地时区能在不同地区正确反映用户看到的时间，同时保留数值偏移避免歧义。
- 替代：本文件下方同日的“显示东八区时间”决定。

### 2026-08-15：工作流报告采用精简格式并显示东八区时间

- 决定：任务报告保留任务、角色、开始/结束时间、总耗时、摘要和验证；最终工作流报告保留目标、进度、任务摘要、整体开始/结束时间、总耗时和验证，移除文件列表、内部角色 ID、冻结时间及重复分段。
- 决定：报告时间统一格式化为 `YYYY-MM-DD HH:mm:ss+08:00`，使用固定 UTC+8 偏移，不改变持久化的 Unix 时间戳。
- 原因：报告用于快速确认交付结果，不需要重复展示架构元数据；固定偏移可跨平台稳定显示东八区时间。

### 2026-08-15：角色切换不重复调用刚完成的自动压缩

- 决定：`agent_settled` 处理待定角色切换压缩时，若当前 session branch 尾部已经是 Pi 的 `compaction` entry，则跳过扩展手动压缩并直接继续任务。
- 原因：Pi 会在 `agent_settled` 前完成内置自动压缩；再次调用扩展的 `ctx.compact()` 会稳定返回 `Already compacted`，该警告不是新的压缩失败。
- 约束：仅跳过明确以 `compaction` 结尾的 branch；其他情况仍调用扩展定制压缩并保留原有错误处理。

### 2026-08-15：项目级 Provider 默认 fail-closed

- 决定：`.pi/role-models.json` 顶层增加 `providerPolicy`；缺少该字段时默认使用 `{ "mode": "locked", "allowedProviders": ["openai-codex"] }`。角色配置、模型选择/循环、会话恢复、工作流和 Agent 子代理共用同一策略；省略 Agent model 继承当前模型，未限定 Provider 的模糊名称直接拒绝。
- 原因：已确认 OpenRouter 调用来自 Agent 子代理显式的 `haiku`/`sonnet` 参数或 agent 类型默认模型解析，不是 Codex 失败后的 fallback。仅约束角色切换无法覆盖子代理模型解析。
- 约束：不修改全局凭据；跨 Provider 只能显式编辑并保存 allowlist，不提供临时解锁或隐式 fallback。当前 Pi 0.84 没有可取消的 `before_model_select`，因此 `model_select` 使用 awaited 安全模型回滚，并在请求前再次校验；未来核心 API 可用后再前移到选择源头。

### 2026-08-15：postinstall 忽略当前 npm 包的 Pi shim

- 决定：`scripts/install-launchers.js` 从 `PATH` 查找 Pi CLI 时，跳过当前包 `node_modules/.bin` 下的 `pi`/`pi.cmd` 等 shim，选择后续实际 Pi CLI 所在目录作为 `pi-usage` 安装目标。
- 原因：Pi 更新 Git 包时会在包目录执行 npm 生命周期脚本，npm 将当前包的 `.bin` 目录置于 `PATH` 首位；若直接取第一个 `pi`，启动器会被复制到临时依赖目录，用户 PATH 中的 `pi-usage` 仍保持旧副本。
- 约束：保留 Windows 和 POSIX 的 PATH 查找，未找到可用 Pi 时仍安全跳过；显式传入安装目标的测试/调用不经过 CLI 查找。

### 2026-08-15：角色配置默认只在当前会话生效

- 决定：运行时角色切换、角色模型配置和工作流配置先保存在扩展内存中的当前会话草稿；只有用户明确执行 `/pi-init save`（保存角色配置）时，才将暂存字段合并写入 `.pi/role-models.json`。
- 原因：模型切换是会话行为，不应因自动职责路由或临时试用模型而污染项目默认配置；显式保存保留了调整项目默认值的能力。
- 约束：保存时读取文件最新内容并只合并当前会话暂存字段；未执行保存不得写入角色配置文件，新的会话清空未保存草稿。

### 2026-08-15：pi-init 与 pi-usage 共用 package 版本号

- 决定：以 `package.json` 的 `version` 作为唯一版本来源；仓库内直接运行 `pi-usage` 时读取该字段，安装到 Pi 可执行目录的启动器脚本在复制时嵌入同一版本；报告标题显示该版本。
- 原因：`pi-usage.js` 会被独立复制到 PATH，运行时不能依赖目标目录旁存在完整 package；复制时嵌入可以避免安装后的版本漂移，同时不维护第二个手写版本号。
- 约束：更新 package 版本后必须重新执行安装器或让 `postinstall` 同步启动器；缺少有效 package 版本时不伪造版本号。

### 2026-08-15：pi-usage 导入使用有界 Appender 和文件事务

- 决定：usage、activity、speed 三类事件通过 DuckDB Appender 写入，每 1024 行 flush；变更文件的删除、事件写入和 `session_files` checkpoint 更新放在同一事务内，speed schema 回填使用全量重建事务。
- 原因：实测 213 MB JSONL 冷导入约 93.8 秒，而原始读取和 JSON 解析约 0.8 秒；逐事件 `connection.run` 是主要写入放大来源。
- 约束：保持单连接顺序写入和现有表结构/统计语义；Appender、提交或元数据更新失败必须回滚，不能留下半个文件的导入结果。

### 2026-08-15：pi-usage 使用流式 JSONL checkpoint 增量导入

- 决定：`session_files` 保存已提交字节 offset、下一行号、cwd、提交前缀尾部 SHA-256、末行换行状态和不完整尾部状态；正常追加从 checkpoint 继续，截断、同尺寸改写、尾部校验失败或旧库缺少 checkpoint 时全量回退。
- 原因：`readFileSync().split()` 会同时保留完整字符串和行数组，且追加 session 不应重复解析已提交内容；不完整 EOF 记录必须等待后续字节补全。
- 约束：只有完整 JSON 行推进 checkpoint；物理行号必须保持稳定；旧 `session_files` 通过 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 升级，下一次变更安全全量重建。

### 2026-08-15：只刷新受影响日期并外显刷新统计

- 决定：duration summary 只按文件新增、全量回退或删除产生的日期集合重算；无文件变化不删除或重建已有汇总。刷新通过可选回调报告开始、文件模式和完成统计，CLI 只在 TTY 输出进度。
- 原因：避免每次 `--update` 重复读取活动事件并重建当天汇总，同时让自动刷新和手动刷新都能区分跳过、追加和全量重建。
- 约束：非 TTY 报表保持兼容；进度统计不是业务数据，不影响导入事务或摘要结果。

### 2026-08-14：最终报告改为整体工作总结与复盘

- 决定：修订“最终交付使用冻结工作流整体报告”中的摘要口径：`state.plan.summary` 仅作为“工作流目标”；最终报告增加“整体工作总结”“工作复盘”和“汇总验证”三个部分。整体总结按冻结任务顺序汇总持久化的完成摘要和进度，复盘汇总冻结时间、实际执行区间和整体耗时，验证按任务顺序汇总真实验证记录。
- 原因：规划摘要表达的是预期目标，不足以代表最终交付；用户需要看到所有任务的确定性总结和可追溯复盘，而不是最后任务的摘要或额外的主观模型生成内容。
- 约束：只使用工作流状态和已有时间边界，不调用模型、不添加依赖；只有最后任务完成时输出；local 与 `subagents` 共用同一 formatter、字段和 TUI 样式；旧状态缺失信息时继续明确显示不可用，不伪造内容。
- 替代：细化并替代下方“最终交付使用冻结工作流整体报告”中“标题和核心摘要使用 `state.plan.summary`”的摘要表述；其整体完成时机、时间口径和执行器一致性约束仍然有效。

### 2026-08-14：最终交付使用冻结工作流整体报告

- 决定：只有最后一个任务完成并使工作流进入 `completed` 时，才输出工作流整体完成报告；报告标题和核心摘要使用冻结的 `state.plan.summary`，并汇总全部任务、验证结果、冻结时间、整体实际开始/结束时间和总耗时。中间任务继续输出任务级完成报告。
- 原因：用户需要区分单个任务交付与整个架构规划的最终交付，避免把最后任务描述或任务耗时误报成工作流整体结果。
- 约束：整体耗时从首个任务实际开始执行到最后任务完成，不计入规划、审阅或调度等待；工作流级时间戳持久化并兼容旧状态回退；local 与 `subagents` 必须使用相同报告格式和现有醒目 TUI 样式；无有效时间边界不得伪造耗时。

### 2026-08-14：工作流完成结果必须保留完整报告

- 决定：`task_workflow complete` 的工具结果渲染器优先显示返回内容中的完整任务完成报告，而不是用工作流进度摘要覆盖它。
- 原因：完成结果本身包含任务摘要、开始/结束时间、总耗时和验证结果；只显示进度会让用户误以为这些信息没有生成。
- 约束：仅调整结果展示，不改变工作流状态机、完成时间戳、session 持久化或普通执行报告语义。

### 2026-08-14：补充非工作流 Agent 执行时间报告

- 决定：对未进入活动 `task_workflow` 的外部 `interactive`/`rpc` 输入，记录一次普通 Agent 执行的首次 `agent_start`、最终 `agent_settled` 和总耗时，并通过不进入 LLM 上下文的 `pi-init-run-timing` session custom entry 在 TUI 展示来源、开始时间、结束时间、总耗时和计时口径。
- 原因：工作流任务已有结构化完成报告，但 `workflowMode: "auto"` 绕过编排的普通执行缺少可见时间信息；普通执行报告可以补充运行时事实，同时不冒充业务任务完成。
- 约束：同一次执行的重复低层 `agent_start` 不重置首次开始时间；活动工作流、subagents 和扩展隐藏续跑不得生成普通报告；reload、会话切换或中断只丢弃未完成的内存计时，不补造结束时间；无效或倒退时间戳不生成耗时。

### 2026-08-14：工作流终态后恢复底部状态摘要

- 决定：工作流进入 `completed` 或 `cancelled` 后，底部 `pi-init` 状态栏显示初始的策略、执行器和“无活动工作流”摘要；控制中心和 `status` 仍保留终态工作流状态供查看。
- 原因：终态工作流不再是当前活动任务，底部状态应反映可继续操作的当前状态，避免残留“已完成/已取消”造成误解。
- 约束：不清除内存或 session 中的终态状态，不影响完成报告、状态查询和历史恢复。

### 2026-08-14：在 Agent 规则中约束 read/edit 工具调用

- 决定：项目及生成模板的 `AGENTS.md` 明确区分 `read` 与 `edit` 参数；编辑前必须重读并直接复制 `oldText`，匹配失败后必须重新读取，不得重复相同替换或使用模糊匹配。
- 原因：减少把 `offset`/`limit` 误传给 `edit`，以及手动改写引号、缩进和换行导致的精确替换失败。
- 约束：继续保留精确字符串替换和修改后 diff 检查，不通过放宽匹配规则换取表面成功。

### 2026-08-14：任务完成时输出基于状态机时间戳的完成报告

- 决定：每个工作流任务进入 `in_progress` 时记录 `startedAt`，完成时记录 `completedAt`；本地完成和 subagents 完成路径都输出统一的任务完成报告，包含任务信息、角色、时间、总耗时、摘要和验证结果。
- 原因：用户需要在任务结束时直接了解交付内容和实际耗时，统一 formatter 可避免不同执行器的输出字段漂移。
- 约束：`startedAt` 在任务实际派发给本地模型或子代理时记录，`completedAt` 在完成时记录；总耗时只使用这两个任务自身时间计算。不得使用模型启动、工作流创建或子代理可选生命周期时间伪造；旧状态的过时开始时间在首次实际派发时刷新。

### 2026-08-14：通过 pi.events 接入可选的 pi-subagents 顺序执行器

- 决定：`task_workflow` 保留主扩展状态机和唯一写入权；新增显式 `workflowExecutor`，默认 `local`，只有配置为 `subagents` 时才通过 documented `pi.events` RPC 委派当前任务，不引入 `@tintinweb/pi-subagents` 依赖或复制源码。
- 原因：复用第三方代理的生命周期、模型和会话管理，同时保持现有工作流默认行为和本地回退；首版顺序执行可避免共享工作区并发修改和合并冲突。
- 约束：子代理只能在共享工作区执行，不自动创建 worktree、并行、合并、提交或推送；结果必须严格符合 `pi-init/task-result@1`，异常结果、RPC/扩展缺失和生命周期失败安全阻塞任务；任务创建时持久化 executor，reload 后不自动重生已绑定的非终态代理，取消/阻塞仅发送 stop 请求而不伪造完成。

### 2026-08-14：通过 package postinstall 同步 pi-usage 独立启动器

- 决定：将跨平台 `scripts/install-launchers.js` 配置为 package 的 `postinstall`，让 `pi update --extensions` 触发 package 安装时重新复制 `pi-usage` 启动器和脚本到 Pi 可执行目录。
- 原因：启动器是独立复制到 PATH 的文件，不属于 Pi package 资源目录；仅更新 package 不会自动替换已安装的启动器。
- 约束：按 `process.platform` 选择 `.cmd` 或 POSIX shell 启动器；找不到 `pi` 时必须安全跳过并提示手动安装，不得阻断 package 更新；npm 禁用 lifecycle scripts 时仍需保留手动安装路径。

### 2026-08-14：工作流策略独立于角色与模型配置并合并到主状态

- 决定：控制中心将工作流策略作为独立的顶层“变更”入口，不再嵌入“变更 · 角色与模型”；主 `pi-init` 状态项同时显示角色模型和工作流策略/进度，保留独立工作流进度菜单用于查看和操作。
- 原因：工作流会改变任务调度、角色切换和会话状态，用户需要在外部直接看到并配置它，不能把它当成普通角色模型字段隐藏。
- 约束：继续使用 `.pi/role-models.json` 的 `workflowMode` 和 `/pi-init config workflow` 持久配置；状态项在无活动工作流时也显示当前策略。

### 2026-08-14：工作流运行时版本不一致必须给出可操作诊断

- 决定：调用工作流策略函数前检查其运行时类型；函数缺失时停止当前规划并提示扩展与 `src/roles.js` 版本不一致，以及 `pi update --extensions`、`/reload` 或本地重启步骤。
- 原因：Pi Git package 的扩展和相邻源码可能因更新/reload 时机不同而混用；继续猜测策略会比明确失败更危险。
- 约束：通过 `1.0.4` 版本升级降低旧安装残留概率，不添加 silently fallback；`workflowEnabled` 兼容和既有工作流收尾行为不变。

### 2026-08-14：任务工作流改为 off/on/auto 策略

- 决定：以 `.pi/role-models.json` 顶层 `workflowMode` 作为规范字段，取值 `off`、`on`、`auto`，默认 `auto`；`off` 拒绝新的 `plan`，`on` 始终编排，`auto` 对不超过 2 个任务跳过状态持久化、调度和角色切换，超过 2 个任务才创建工作流。
- 原因：保留复杂任务的持久化顺序编排，同时避免简单任务承担规划后的隐藏续跑和模型切换开销。
- 约束：配置入口仍为 `/pi-init config workflow`；旧项目缺失 `workflowMode` 时，`workflowEnabled: true/false` 映射为 `on/off`，两个字段同时存在时新字段优先；模式变化不阻止既有工作流的 status、complete、block、resume、retry、cancel。

### 2026-08-14：移除自研并行开发实现并保留顺序工作流

- 决定：删除 `parallel_develop` 工具、隔离 Git worktree/Pi worker 运行时代码及其专用测试、fixture、模板和文档说明；不添加或配置第三方替代品。保留 `task_workflow`、`switch_role`、角色模型配置和脚手架生成。
- 原因：项目改用第三方并行开发方案，继续维护自研并行编排会重复建设并扩大运行时、跨平台进程和 worktree 合并的维护面。
- 约束：不保留兼容别名、休眠代码或过时 API 指引；历史决策和会话记录保留，并由本条决策取代涉及自研并行实现的后续运行时约束。

### 2026-08-14：架构规划后采用持久化顺序任务工作流

- 决定：新增 `task_workflow` 工具和项目模板规则。架构角色通过 `plan` 冻结摘要、约束、任务、依赖、文件范围和验收标准；开发测试角色每次只执行一个当前任务，完成并提交真实验证后自动进入下一个任务。
- 原因：仅靠 Skill 中的角色说明无法保证架构输出真正转化为可执行任务，也无法在多回合之间可靠记住当前任务；扩展状态机和 session custom entry 能让任务进度跨回合、reload 和 resume 恢复。
- 约束：默认不询问用户选择；只有初始明确要求先审阅架构、缺少产品决策/权限/凭据、破坏性操作确认或真实阻塞时暂停。工作流最多 12 个任务，任务依赖必须无环；模型未提交完成/阻塞结果时最多自动提醒 2 次后暂停。
- 约束：共享接口、测试契约或顺序依赖的任务走串行工作流；并行开发不由本项目内置实现负责。
### 2026-08-13：用 pi-token-speed 自定义 session 采样计算模型平均 TPS

- 决定：`pi-token-speed` 在每个成功的 assistant 响应完成后，通过 `pi.appendEntry("pi-token-speed", data)` 持久化 provider、实际响应模型、输出 token 和有效生成毫秒数；`pi-usage` 增加 `speed_events` 表并按 provider/model 汇总 `输出 token总数 / 有效生成秒数总数`。

- 约束：保留独立 Pi 进程和隔离 worktree；仅在任务真正独立、契约冻结且足够大时使用并行，小任务或共享 DOM/API/测试契约的任务仍由单 worker 处理。

### 2026-08-06：并行子代理采用事件流和分级故障接管

- 决定：并行 worker 使用 Pi JSON 事件流，由主扩展实时更新每个任务的状态、当前工具、耗时和最后活动；基础设施错误最多自动重试一次，代码/测试错误交由主开发测试工程师接管，架构或合并冲突交由架构师处理。
- 原因：一次性等待子进程结束会让主界面长期显示 working，错误也无法区分责任人；事件流能提供进度，分级策略能避免盲目重试代码错误。
- 约束：失败任务的隔离 worktree、prompt 和 stdout/stderr 日志必须保留；只有全部任务成功且主工作区未变化时才自动合并和清理。

### 2026-08-06：自动跨角色切换在大上下文时压缩

- 决定：仅在 `auto` 模式发生真实跨角色、且切换前上下文使用率达到 50% 时，于当前回合结束后触发一次定制压缩；压缩成功后发送隐藏续跑消息继续当前任务。
- 原因：角色边界是自然的上下文交接点，大上下文需要先提炼目标、决策、进度、文件、验证结果和下一步；低于阈值或非自动模式不应增加额外模型调用。
- 约束：首次选角、同角色重复切换、未知上下文、`confirm` 和 `manual` 均跳过；压缩失败不回滚已完成的模型切换，也不阻断后续工作。

### 2026-08-06：并行 worker 按目标平台处理 CLI、路径和进程

- 决定：Windows 的 Node/Bun 备用入口通过 `cmd.exe` 加转义参数启动 `pi.cmd`；POSIX worker 使用独立进程组，Windows 使用 `taskkill /t /f` 终止子进程树；文件范围比较读取 Git `core.ignorecase`。
- 原因：Node `spawn(..., { shell: false })` 不能直接启动 Windows `.cmd`，大小写敏感性由实际文件系统和 Git 配置决定，单独杀父进程会遗留工具子进程。
- 约束：不引入新的运行时依赖；三平台回归由 GitHub Actions 矩阵执行，当前本地只完成 Windows 验证。

### 2026-08-06：会话恢复时只恢复唯一匹配的角色

- 原因：角色状态原先只存在扩展内存中，reload、resume 或次日重新打开会丢失，导致第一次真实跨角色无法触发上下文压缩。
- 约束：恢复只识别身份，不主动覆盖用户当前模型或推理强度；手动改过模型/推理强度时继续视为未知角色。

### 2026-08-09：用事件间隔估算 pi-usage 使用时长

- 决定：增加 `duration_summaries`，记录指定日期的活跃时长、模型等待时长和 session 跨度；活跃事件间隔不超过 5 分钟才累计，模型等待间隔最多累计 30 分钟。
- 原因：当前 Pi session JSONL 没有统一的模型调用开始/结束事件，只能基于带时间戳的消息和工具事件进行可解释的近似估算。
- 约束：模型等待时长不是精确的 API 延迟，也不代表用户实际操作时间；session 跨度仅作参考。

- 原因：从当前时刻开始会漏掉当天较早的 Git commit，且与按 entry 本地日期筛选的 usage/activity 数据不一致。

- 原因：避免每次查看都扫描文件，同时避免用户忘记更新导致数据长期停留在旧快照。
- 约束：DuckDB 的 `usage_state` 保存全局检查时间和日期；文件变化后按文件大小/修改时间增量导入，受影响日期的派生汇总一并刷新。

- 约束：仍保留待压缩状态，压缩成功后才注入隐藏续跑消息；压缩失败不回滚已完成的模型切换。

### 2026-08-09：用 DuckDB 汇总跨 session 用量和 Git 代码变化

- 决定：增加 `pi-usage [YYYY-MM-DD] [--db <path>]`，将 Pi JSONL 中的 usage 事件导入 DuckDB，按模型汇总 input、output、cache token、调用次数和费用；工具内部摘要单独归为 `Tools/summaries`。

- 约束：增量更新通过 `session_files` 保存文件大小和修改时间；变化文件会删除后重导其 usage/activity 事件，删除的 session 文件也会同步清理。
