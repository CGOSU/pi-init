# 设计决策

本文件记录已经确认且会影响后续实现的决定。临时想法和普通操作记录不写入此处。

## 记录格式

每项决策应包含日期、决定、原因和约束。如果后续改变决定，应注明被替代条目，而不是删除历史。

## 已确认决策

### 2026-08-06：在 AGENTS.md 写入初始化时的宿主环境快照

- 决定：`init_project` 和 `/init-project` 在生成的中英文 `AGENTS.md` 中记录 `process.platform`、`process.arch` 及平台相关命令约定；不把这类规则放进项目 Skill。
- 原因：`AGENTS.md` 是 Pi 默认加载的长期项目上下文，Skill 只在任务匹配后按需加载；系统信息应先于任务路由生效。
- 约束：这是初始化宿主环境的快照，不承诺项目部署目标；工具仍需在实际运行环境重新探测命令。跨项目固定规则使用 Pi 全局 `~/.pi/agent/AGENTS.md`，而不是 `settings.json`。

### 2026-08-04：保留项目级 Skill 作为默认产物

- 决定：默认生成 `AGENTS.md`、四个项目记忆文档和 `.pi/skills/<slug>/SKILL.md`。
- 原因：项目级 Skill 是本扩展的明确目标产物，可为相关任务提供稳定触发入口。
- 约束：长期规则只维护在 `AGENTS.md`；Skill 正文保持精简，不复制文档索引和规则正文。

### 2026-08-04：默认模板采用 CGOSU 工作流

- 决定：中英文 `AGENTS.md` 模板均包含 CGOSU 知识库和仓库 Git 身份规则。
- 原因：该扩展当前服务于 CGOSU 项目初始化，两个语言版本应保持相同策略。
- 约束：其他团队使用前需修改对应模板；暂不增加配置层或团队配置系统。

### 2026-08-04：职责路由使用可覆盖的默认模型映射

- 决定：复用现有项目级 Skill 按交付物路由；默认将架构师映射到 `openai-codex/gpt-5.6-sol:max`、开发测试工程师映射到 `openai-codex/gpt-5.6-terra:high`、文档与提交工程师映射到 `openai-codex/gpt-5.6-luna:medium`。
- 原因：明确映射才能通过 Extension API 全自动切换；`.pi/role-models.json` 允许项目在不修改 Skill 或扩展代码的情况下替换模型。
- 约束：只读取已信任项目的映射；模型不存在、缺少凭据或配置无效时停止职责切换并报告错误。提交和推送仍需用户明确授权。

### 2026-08-06：开发测试职责改用 Luna 模型

- 决定：将开发测试工程师默认映射从 `openai-codex/gpt-5.6-terra:high` 改为 `openai-codex/gpt-5.6-luna:max`。
- 原因：按当前工作流选择 Luna，并提高推理强度以支持实现、调试和测试。
- 约束：架构师和文档与提交工程师的默认映射不变；项目仍可通过 `.pi/role-models.json` 覆盖。

### 2026-08-06：架构规划后的开发测试任务并行执行

- 决定：新增 `parallel_develop` 工具；架构师输出至少两个独立工作包后，由多个 `developer-test` 子代理使用同一职责模型并行执行。
- 原因：Pi 的当前会话只能切换一个模型；独立子进程和隔离 Git worktree 才能同时运行多个开发测试工程师并安全合并修改。
- 约束：主工作区必须干净；每个任务必须声明不重叠的文件范围；最多并行 4 个任务；子代理不得提交或推送，合并后由主会话统一检查 diff 和完整测试。

### 2026-08-06：支持自动、确认和手动职责模式

- 决定：在 `.pi/role-models.json` 顶层增加 `mode`；`auto` 立即切换，`confirm` 在自动边界询问，`manual` 只接受用户 `/role` 选择；`/role-mode` 提供当前会话临时覆盖。
- 原因：同一套职责模型既要支持无人干预的自动流程，也要支持高风险任务的人工确认和完全手动控制。
- 约束：确认模式默认选中自动建议；手动模式不会被 `switch_role` 或 `parallel_develop` 静默覆盖，必须由用户先选择正确职责。

### 2026-08-06：并行开发默认拒绝隐式信任和重命名范围绕过

- 决定：`parallel_develop` 仅允许在受信任项目中运行；子代理使用 `--no-approve` 和文本输出模式；文件范围检查关闭 Git 重命名检测。
- 原因：并行子代理会执行代码和写入 worktree，不能因为自动化流程隐式提升项目权限；Git 重命名检测可能隐藏范围外源文件的删除。
- 约束：主工作区仍必须干净，任务范围必须不重叠；未受信任项目需由用户先完成信任确认。

### 2026-08-06：职责模型配置使用单一持久来源

- 决定：初始化向导和 `init_project` 支持配置三个职责的 provider、model 和 thinkingLevel；运行时通过 `/role-config` 更新 `.pi/role-models.json` 并立即应用。
- 原因：自动职责路由、并行开发和重启后的行为必须读取同一份项目配置；Pi 原生 `/model` 和 `Shift+Tab` 保留为会话级临时切换。
- 约束：只从当前可用模型中选择，并按模型能力限制推理强度；不增加第三层会话覆盖配置或复杂自定义 TUI。

### 2026-08-06：职责模型选择先搜索过滤再进入列表

- 决定：初始化和 `/role-config` 的职责模型选择先输入可选搜索词，再仅在匹配的 provider/model ID 或模型名称中选择。
- 原因：模型列表可能较长，复用现有输入和选择 UI 即可降低查找成本，不引入新的自定义 TUI 组件。
- 约束：空搜索词显示全部模型；无匹配时终止本次配置并提示重新执行。

### 2026-08-06：用户入口收敛为 `/pi-init` 控制中心

- 决定：移除 `/init-project`、`/role`、`/role-mode` 和 `/role-config` 的独立命令，统一通过 `/pi-init` 菜单和 `init`、`advanced`、`config`、`role`、`mode` 子命令访问；保留模型工具名供 LLM 调用。
- 原因：原流程把内部职责 ID 和配置细节直接暴露给用户，默认初始化需要多次弹窗和额外 `/reload`；一个控制中心能减少记忆成本并提供统一状态摘要。
- 约束：高级用户仍可使用直接子命令；职责模式仍区分会话临时覆盖与项目持久配置；不修改 Pi 原生 `/model` 和 `Shift+Tab`。

### 2026-08-06：快速初始化自动推断元数据并在当前项目完成后 reload

- 决定：快速初始化读取 `package.json`、锁文件和目录名推断项目名、描述、包管理器和测试命令；成功写入当前项目后调用 `ctx.reload()`。
- 原因：默认路径不需要重复输入已存在的项目元数据，也不应要求用户手动执行 `/reload` 才能加载新 Skill。
- 约束：高级初始化仍允许覆盖推断值；无法读取元数据时回退到目录名和空白可选字段；目标是其他目录时不自动切换当前会话资源。

### 2026-08-06：TUI 配置使用 Pi 原生主题组件和即时搜索

- 决定：控制中心使用 `DynamicBorder`、`SelectList`、`Input` 和当前主题色；TUI 模型选择在同一界面实时筛选，结果默认折叠并仅在展开时显示详细指标。
- 原因：复用 Pi 已有 TUI 能力可以改善层级和可读性，不引入新的 UI 框架或自定义主题系统。
- 约束：RPC 模式保留 `ctx.ui.select/input` 降级路径；模型搜索仍受当前模型范围和凭据限制。

### 2026-08-06：控制中心优先展示状态和摘要而不是完整细节

- 决定：`/pi-init` TUI 菜单显示模式、职责、当前模型的状态卡片；菜单项按初始化和职责分组并使用图标；初始化通知默认只显示文件数量和冲突摘要，完整文件列表保留在工具展开结果中。
- 原因：状态栏和通知中的长路径、完整文件列表会挤压选择区域；用户需要先做选择，再按需查看细节。
- 约束：状态信息必须随实际当前模型和推理级别更新；窄终端由 Pi 的 Text/SelectList 自动换行和截断，不增加独立响应式布局系统。

### 2026-08-06：并行子代理采用受限并发和可量化性能指标

- 决定：`parallel_develop` 默认最多同时运行 2 个 worker，最多接受 4 个任务；高频模型输出按 250ms 节流，工具和阶段状态仍即时上报。
- 原因：实际模型请求远慢于 worktree 创建，盲目并发会增加 provider 限流、长尾和集成等待；阶段指标用于区分模型耗时与本地编排耗时。
- 约束：保留独立 Pi 进程和隔离 worktree；仅在任务真正独立、契约冻结且足够大时使用并行，小任务或共享 DOM/API/测试契约的任务仍由单 worker 处理。

### 2026-08-06：并行子代理采用事件流和分级故障接管

- 决定：并行 worker 使用 Pi JSON 事件流，由主扩展实时更新每个任务的状态、当前工具、耗时和最后活动；基础设施错误最多自动重试一次，代码/测试错误交由主开发测试工程师接管，架构或合并冲突交由架构师处理。
- 原因：一次性等待子进程结束会让主界面长期显示 working，错误也无法区分责任人；事件流能提供进度，分级策略能避免盲目重试代码错误。
- 约束：失败任务的隔离 worktree、prompt 和 stdout/stderr 日志必须保留；只有全部任务成功且主工作区未变化时才自动合并和清理。

### 2026-08-06：自动跨角色切换在大上下文时压缩

- 决定：仅在 `auto` 模式发生真实跨角色、且切换前上下文使用率达到 50% 时，于当前回合结束后触发一次定制压缩；压缩成功后发送隐藏续跑消息继续当前任务。
- 原因：角色边界是自然的上下文交接点，大上下文需要先提炼目标、决策、进度、文件、验证结果和下一步；低于阈值或非自动模式不应增加额外模型调用。
- 约束：首次选角、同角色重复切换、未知上下文、`confirm` 和 `manual` 均跳过；压缩失败不回滚已完成的模型切换，也不阻断后续工作。

### 2026-08-06：并行 worker 按目标平台处理 CLI、路径和进程

- 决定：Windows 的 Node/Bun 备用入口通过 `cmd.exe` 加转义参数启动 `pi.cmd`；POSIX worker 使用独立进程组，Windows 使用 `taskkill /t /f` 终止子进程树；文件范围比较读取 Git `core.ignorecase`。
- 原因：Node `spawn(..., { shell: false })` 不能直接启动 Windows `.cmd`，大小写敏感性由实际文件系统和 Git 配置决定，单独杀父进程会遗留工具子进程。
- 约束：不引入新的运行时依赖；三平台回归由 GitHub Actions 矩阵执行，当前本地只完成 Windows 验证。
