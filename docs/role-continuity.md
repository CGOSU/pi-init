# 连续任务与轻量角色交接

普通任务由匹配角色连续调查、修改和验证，必要时交给文档角色收尾；简单任务不强制建立工作流。确需架构决策时，由架构师复用现有事实决策，缺少关键事实才集中补查。角色切换不代表新任务，不应重做未失效的调查或验证。

## 模型提交与运行时身份

模型正常调用 task_workflow 只提交业务动作、完成摘要、理由及真实验证；无需抄写 workflow/session/recovery/attempt/handoff。运行时在 Provider 请求开始捕获身份，再绑定到实际助手消息和其工具调用，执行时校验会话、角色代次、任务及活动 branch。嵌套调用只能继承已知父工具身份。身份不是执行时从最新状态推导，旧回合不能给新任务提交结果。

完整身份和协调短引用保留兼容，显式过期字段不会被覆盖。缺少真实消息绑定的隐式结果会失败；status 保持只读。原始 session 和消息 details 中的审计身份继续保留。

## 普通流程与正式证据

已 ready 的旁账不再强制普通计划生成任务契约；默认不走 request/report/review/accept/contract 仪式。主动携带 contract 或已绑定的正式旧工作流继续校验有效来源、当前 revision 和关键未决问题。正在进行或 blocked 的显式取证不可通过删契约绕过；无关账本的恢复错误不污染普通计划。

正式证据接受后，若用户原目标仍需实现，架构角色继续规划，不等待用户再次催促。

## 暂停与恢复

paused/replanning 属于未结束工作流，不显示为无活动工作流。暂停视图依据当前 branch 快照保留目标、相关事实及完整工具调用/结果配对，不重新塞回全部历史，也不把旧交接当作执行授权。

确认角色只解除职责恢复门，不解除任务暂停。暂停、重规划或恢复未完成时禁止编辑、写入、普通 shell 和未知工具执行，允许状态查询与既有只读核对；architect 的工具边界不变。

结果未知的 retry 必须由用户核对副作用后执行 /pi-init workflow retry <taskId> --confirm-unknown-outcome，或通过工作流面板明确确认。模型传 true 不构成授权；旧结果仍保留，不自动重放。既有退役状态和异常诊断继续 fail closed。

## 验证边界

自动化回归检查身份绑定、过期消息拒绝、普通/正式流程分离、暂停执行门和恢复上下文；不等同真实 Provider/TUI 性能基准。速度对照需固定任务、模型和推理强度，观察首次修改时间、模型轮次与恢复前后输入规模。
