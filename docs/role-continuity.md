# 连续任务与轻量角色交接

普通任务由匹配角色连续调查、修改和验证，必要时统一文档/Git收尾；简单任务不强制工作流。角色切换不代表新任务，不重做未失效的调查或验证。

## 角色选择与连续性

- 活动工作流的显式任务角色优先于模型自行判断；当前任务未退出时，沿用既有运行时角色守卫，不因分析 Bug 或读取 API 文档切角。必要计划变化先登记 request-replan，再通过真实 complete/block 到达安全边界。
- 无活动任务时优先用户明确指定角色，否则按交付物选择；同一交付物内连续调查、实现和验证，独立交付物或必要架构决策才交接。无工作流仅有提示指导，未新增任务状态机或硬绑定，不能保证模型总能正确选角。
- architect 可为当前决策使用明确白名单中的本地只读工具；不得 shell/codemode/MCP、写入或执行，也不得作为工作流执行角色。恢复、身份、用户停止和未知结果保护不变，用户指定角色不豁免安全守卫。

结构审阅中的读取、分析、建议和登记属于同一交付物；不逐文件切换调查、架构和登记角色。必要的新设计决定按模块汇总已有来源后交接。代码执行者在交付给文档角色前处理本次改动的格式问题，避免收尾因空白修正重新规划。

## 身份与进展

- 模型提交业务参数和真实结果；运行时在Provider请求/实际消息/工具调用之间绑定workflow、session、plan、recovery、task、attempt和handoff。旧角色、旧branch或旧回合不得套用最新身份。
- status只读；checkpoint必须有真实executing绑定，即使填写显式旧身份也不能绕过。完整历史结果保存在原session，工作记忆只保存有界摘要和真实来源。
- 阶段完成或验证结束后登记成果、剩余项和下一步。可用status按来源ID读取原结果，不因模型视图归档而重跑。历史通过不证明当前版本有效，工具成功不等于任务验收。

## 单一扁平工作流

- plan/replan由architect负责，且其不得作为工作流执行角色；developer-test在同一实现交付内连续调查、实现、测试并完成直接必要说明及已授权整项Git收尾。独立文档/版本或明确指定的统一收尾由docs-commit负责，活动任务显式分工优先。正式证据、结构任务契约/clarify和旧嵌套执行已退役，缺少关键事实或权限用block。
- request-goal只插入同一队列的目标分组；依赖先于priority，不创建parentStack、子执行器或父层返回协议。完成一个分组不等于全部任务验收。
- 正常最终回复与单次确定性兜底共用完成视图；报告阶段不执行Git/工具，不补称未观察到的验证、提交或推送成功，不创建自动模型回合。

## 暂停、旧记录与恢复

- paused/replanning均是未结束工作流。暂停视图依据当前branch快照保留目标、工作记忆与完整工具组，旧交接不是执行授权；确认角色不解除任务暂停。
- 结果未知的retry必须由用户核对副作用后执行 /pi-init workflow retry <taskId> --confirm-unknown-outcome，或在面板显式确认。模型传true不构成授权，不自动重放。
- 旧正式取证/结构契约/澄清/嵌套记录统一返回WORKFLOW_FEATURE_RETIRED；Runtime状态继续明确退役。只读诊断保留来源ID，受信任且空闲、用户确认副作用后可用discard-recovery隔离指定记录；原数据不改写，隔离不等于成功或取消。
- 旧角色配置在统一归一化入口解释，暂存、读取和保存共用规则。读取/更新功能不会自动写入项目配置，只有明确save才持久化。

## 模型请求失败后的续接

- 最终Provider error不自动触发额外模型回合；SDK中间错误后成功不误停。资格按请求开始时的身份和执行边界判断，不按错误文字、零token或摘要判断。
- 当前运行实例仅对可信executing任务提供快续接：唯一任务锚点、角色/模型/恢复身份匹配，根工具与嵌套执行均结束、结果完整，当前branch工具组完整；请求捕获到失败期间没有新增工具活动。明确的原生只读失败可以是已知结果，写入失败和缺失结果仍不确定；codemode仅在完整SDK嵌套回执与自身调用记录一一对应、全部属于允许的只读操作时接受，不解析脚本猜测副作用。复用已有请求绑定、工具生命周期和配对校验，不建立第二套调度器。
- 满足条件时复用停止开关阻止自动请求，不将任务标为outcomeUnknown；用户明确“继续”时再次校验原身份、工具边界、宿主空闲、排队消息及持久化，沿原attempt/handoff续接，不调用任务retry、不重发首次任务锚点。额度/认证错误同样先等待原因解决，不自动循环请求。
- 已进入请求失败暂停后，允许的 `status`、`read`、`grep`、`find`、`ls` 观察在结束且回执完整时不使续接失效；观察进行中、缺回执、其他工具活动及身份/分支变化仍拒绝继续。
- 继续条件失效、停止记录保存失败等保持停止；必要时reload后走已有恢复流程。reload、进程重启、分支变化、旧未知结果和业务block不自动获得快续接资格；不改写旧session，也不把用户人工验收与网络恢复混为一谈。

## 用户确认的会话交接

- 普通会话交接不要求建立工作流或伪造task/attempt/handoff身份。当前已确认的非architect执行角色可用 `session_handoff` 准备显式短背景；未结束工作流不能借普通路径绕过既有交接和恢复门。`/pi-init fresh` 是两类会话共用的用户入口，`/pi-init workflow fresh` 保留兼容。
- 普通快照绑定运行时核对的来源session、项目和branch，内容记录目标、约束、完成/待办、带来源的历史验证、未知项、下一步及其他必要来源。它仅是用户确认的历史声明，不是新验证、工作流检查点、旧角色身份或执行授权；不搬运全部工具历史或思考签名。新输入、非准备工具活动或branch变化会使快照失效，应在当前执行结束、现场稳定时准备后直接fresh。
- 用户命令会预览完整交接背景并等待确认，再重核现场与持久化；目标经既有session替换生命周期创建，只写入选定背景和来源，不自动续跑，用户需在新会话自行继续。若发生未知结果，来源继续冻结，不重复创建；先核对目标，目标已有待核对记录时可在目标再fresh作幂等核对。活动工作流仍复用原有交接包及源/目标安全门。
- 70%容量提醒不自动切session；单次cache miss估算额外成本达到$0.50且UI可见时，每session仅给一次建议，状态栏显示已发次数。该估算不是账单或缓存前缀一致性证明；提示不自动准备交接或换会话。手动交接仍不保证Provider cache hit或费用下降，真实Provider A/B未验证。操作细节见[README](../README.md#容量提醒与手动新会话)及公共[运行时操作参考](../skills/pi-init-role-routing/references/runtime-operations.md)。

## 验证边界

长任务优先在最小代表性贯通链路可运行时验证影响后续正确性的关键假设，再按风险完成其余已确认验收；不默认扩成每项任务的设备或E2E验收。自动回归覆盖身份、持久化失败、未知结果、分支隔离、暂停门和上下文保留，不等于真实Provider/TUI收益。性能对照须固定任务、模型和推理强度，观察重复调查、验证及达到验收的实际成本；提示正文体积变化和离线回归不证明模型质量、速度或成本改善。
