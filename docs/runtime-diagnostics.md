# 运行黑匣子

运行黑匣子默认在可信项目启用。正常只在回合结束保存统计摘要；错误出现时自动保存有限的前后现场，不需要提前开启详细日志。使用 `/blackbox` 查看本地问题汇总，不调用模型、不加入会话上下文、不改变工作流。重新加载扩展或重启 Pi 后生效。

## 模式

- 不设置 `PI_INIT_HANDOFF_LOG`：自动黑匣子。
- `PI_INIT_HANDOFF_LOG=0`：完全关闭采集和落盘，命令显示已关闭。
- `PI_INIT_HANDOFF_LOG=1`：兼容原详细诊断模式，写 `.pi/logs/handoff.jsonl`，用于主动排查；此模式不另外写黑匣子问题包。原离线报告命令保持可用。

开关在扩展加载时读取，改变后需要 reload 或重启。

## 自动记录什么

- 工具错误与非零退出码、业务拒绝、Provider HTTP 错误、assistant error、压缩失败。
- 恢复错误或恢复持久化失败状态首次被观察到时留证。
- 压缩长等待标记为疑似卡住；交接派发未知结果单独记录，不认定失败、不自动重放。最终报告兜底发送失败单独记录。
- 用户取消、正常暂停、缺失结束事件不自动认定为网络故障。业务拒绝不直接认定为产品 bug。

同类问题按类别、稳定错误码、阶段和工具名称分组，不把动态调用 ID 放进问题指纹。每个采集窗口内新问题只提醒一次；同一工具调用的同类重复结果去重。重启、session/branch 切换建立新窗口，汇总跨窗口合并观察次数。HTTP 错误与 assistant 错误可能来自同一请求，不能相加当失败请求数。

## 文件和边界

文件为 `.pi/diagnostics/runtime.jsonl`，超过 2 MiB 轮转，只保留当前文件和 `.1` 备份。与详细日志复用本模块的有界写队列、轮转和一次失败停用处理；仍独立保存脱敏记录，详细日志不套用黑匣子的 7 天保留期或超大行丢弃策略。写入或查看时忽略/清理超过 7 天未更新的文件；不是后台定时删除，也不保证单文件内每条记录均小于 7 天。

内存缓冲最多 64 条/32 KiB，每窗口最多 24 类问题。首次异常立即异步排队保存异常前最多 16 条事件和当前快照；后续有界保留首次与最近事件，总数最多 32 条。在同类问题再次触发时更新 latestTrigger/latestSnapshot，保留首次 snapshot；在 settled/shutdown 更新问题记录。记录包含扩展 package 版本 `extensionVersion`、`id`、`captureId`、累计 `count`、首次/最近时间、截断标志。更新记录不是新问题：汇总按 runtime/capture/session/id 取最后一次，再跨窗口相加，不累加同一窗口的历史 count。

写队列最多 32 条；过载时丢弃，后续记录以 `dropped` 披露。问题类别超限记录 `overflow`。快照超过 8 KiB 则省略并标记，长现场以 `evidenceTruncated`/`incomplete` 标记，不能据有限窗口推断完整执行顺序。轮转、过载、强退或缺失钩子均会使证据不完整；没有记录不代表没有故障。强退可能丢失未落盘记录，不会补判为崩溃或自动恢复任务。

正常摘要记录回合观察耗时、到达诊断观察器的工具调用次数、Provider 请求钩子次数、已报告的 token 字段及异常观察数，并保存实际 Provider/model、职责、推理强度、回合结束观察和配置变化标志。调用到达不等于已执行成功；耗时不是纯推理/网络时间。缺失用量不补零、不估算费用。正常 assistant stop 仅表示正常结束观察，不证明任务完成。

## 统一诊断控制面板与本地维护

`/pi-init → 运行诊断` 和 `/pi-init diagnostics` 打开同一控制面板；`/blackbox` 无参数仍显示原状态汇总，`/blackbox menu` 打开诊断面板。面板同时报告项目及本机全局诊断的实际路径、可读性、当前进程写入计数/状态及观测盲区；这些只是本次检查和本进程状态，不是跨进程健康证明。

- 项目日志位于 `<项目目录>/.pi/diagnostics/runtime.jsonl`，轮转备份为 `runtime.jsonl.1`；与黑匣子原有轮转策略一致，单文件超过 2 MiB 时轮转，最多保留当前文件和一份备份。它仍遵循可信项目和 `PI_INIT_HANDOFF_LOG` 开关。
- 本机全局日志位于 Pi SDK `getAgentDir()` 实际解析目录下的 `diagnostics/pi-init/runtime.jsonl`，备份为 `.1`；不硬编码用户目录。只记录 pi-init 自身可观测的一组有限故障类别，不复制项目会话正文。单文件上限 1 MiB、保留期 7 天，最多当前文件和一份备份；超龄/超限文件在后续写入时清理，不是定时清理。
- 项目与全局记录用事件、项目、会话关联标识连接；标识为哈希值。可观测性不能覆盖扩展加载前、宿主未暴露或未被 pi-init 观察到的故障。
- `/blackbox export <project|global> <新文件路径>` 或面板导出，只导出所选范围最多最近 256 条记录及有限白名单元数据；关联标识再次哈希，不含消息/正文、快照、配置或工具内容。目标以独占新建方式写入（不覆盖），仅本机保存，不上传。遇到损坏、权限、超限或无记录会明确失败。
- `/blackbox clear <project|global>` 或面板清理必须在可信项目中交互确认，只移除所选范围的 `runtime.jsonl` 和 `.1`；不清理旧版详细日志、工作流状态或会话文件。取消无副作用；清理后仍可产生新记录。IO 中途失败可能已部分删除，已删除内容不可恢复；导出写入失败可能留下不完整的新文件。
- 当前版本的项目/全局写入者及维护操作共享目录锁，锁等待约 2 秒后失败，不抢占遗留锁；旧版进程不共享此锁，维护前应关闭旧实例。遗留 `runtime.lock` 不会自动移除。锁仅保护合作的当前版本进程，不是跨版本协调保证。

自动模式不采样文件 stat，不计算普通工具输入/输出正文指纹，不记录提示词、源码、命令、错误正文、请求 payload、headers 或模型回复。只保留有限事件元数据与现有脱敏状态快照；身份、模型名称等元数据仍可能敏感，分享文件前需要人工检查。脱敏导出只包含固定安全分类/事件、时间、计数和再次哈希的关联字段。

写入异常只提醒一次并停用记录，不影响工具结果或工作流。新目录权限为 0700，新日志为 0600。未信任项目不采集、不读取。不会自动重试、恢复、提交代码或调用模型分析；不更改未知副作用的安全门。

## 第二版：循环线索、耗时基线与版本观察

- 复用现有 `workflowProgressObservation` 的 repeated-state、repeated-revision、state-cycle 判断，不再建立另一套循环检测器。只在运行/重规划状态首次观察到新的疑似循环时留证，记录稳定错误码、窗口大小等结构化数据，不记录方向、任务或证据正文。持续同一疑似循环不重复提醒；开始时已存在的疑似循环或恢复错误仍把每个回合标为 `degraded`，不会混入健康基线。正常暂停不触发新的循环判断。
- 耗时基线仅在本扩展实例内积累，按实际 Provider/model、职责、推理强度隔离；每配置最多 64 个样本，最多 8 个配置。至少 8 个完整、正常 stop、无异常观察/持续降级/中止/丢弃/溢出/配置变化的回合后，后续同配置回合耗时超过 `max(1000ms, p95 × 2)` 才记录 `ROUND_DURATION_OUTLIER` 疑似慢回合。异常慢样本不反过来抬高基线。项目切换清空基线，重启重新积累，不从历史文件自动预热。只在回合结束时判断，不是后台超时看门狗。
- `/blackbox` 增加回合总数、正常结束/未知/中止观察、按 package 版本与配置分组的可用样本数、耗时 p50/p95 和已报告 totalTokens 的 p50。分位数使用 nearest-rank。缺失用量不补零；旧版无维度/结束信息的记录仍可展示，但不冒充可比样本。
- 同配置至少两个 package 版本各有 8 个可用样本，并有可靠时间顺序时，展示最近两个观测版本的耗时中位数比值。token 比值还要求两边各至少 8 条已报告 totalTokens；分母为零则显示未知。回合按 runtime/capture/session/run 去重。模型、职责、推理强度不同或回合中观察到配置变化均不作直接版本对照。

版本来自 package.json；源码修改但 package 版本未变时不会自动拆成两个发布版本。不同任务复杂度、项目阶段和外部服务状态未受控，因此比值只说明同配置样本的观察差异，不证明修复带来提速、成功率提升或省钱。基线疑似异常也不是故障定论，不触发重试、暂停、切角或自动优化。真实收益仍需后续真实会话验证。

## 运行时收敛后的补充观测

- 同一工具调用的 routing 提议、守卫拒绝与结果继续保留为不同事件，但使用规范化工具身份和 toolCallId 关联计数；8 次切角拒绝计 8 次，不再拆成两个各 8 次的问题组。不同工具即使错误码相同仍保留独立归属。
- `context.budget_checked` 记录当前窗口 tokens/contextWindow/percent 与 decision/reason。正常阈值、模式、冷却、已有操作和门禁判断不是故障，不创建问题通知；回合摘要的 budget 保存检查次数、判断分布和最近一次脱敏观测。实际压缩失败仍由 compaction.settled 留证。
- `provider.request_summary` 关联本实例的请求观察号、HTTP 状态、头/响应/assistant 钩子是否观察到及白名单连接错误码。健康请求只聚合到回合摘要 providerObservations；异常/中断请求可以另留有限诊断记录，报告按回合去重，不与聚合摘要相加。缺少观察不等于网络失败，不推断启用前请求或宿主真实重试次数。不会保存错误正文、payload、headers，也不新增自动网络重试。
- 重复业务拒绝终止和用户停止属于独立执行保护，不受日志开关控制；它们并非黑匣子根据统计自行恢复或修改任务。停止保留成果，不伪造任务完成；活动执行中断仍走未知结果保护。

## 执行记忆与日志边界

当前 session 的 `pi-init-task-memory` 快照是任务工作记忆，不是黑匣子，也不随诊断开关关闭。它索引已有 SDK 工具结果，保存有界成功/失败摘要、checkpoint、剩余项和真实来源；原结果可通过 `task_workflow(status, evidenceIds=[来源ID])` 读取。摘要可能保留原结果敏感内容，按私有 session 处理，不应混入黑匣子分享包。它不接受需求、不授予执行权、不派发或重跑任务。设计、边界与验收见 [执行记忆架构](execution-memory-architecture.md)。

## 真实会话观测修正

- 支持 headers 钩子先于 request 钩子出现：只在同项目、session 和回合内暂存一次无请求归属的 headers 观察，下一请求消费；新回合、branch/session 生命周期和 settled 清除暂存，不记录 headers 正文。该关联仍不是宿主请求 ID，不推断并发请求或真实重试。
- `providerObservations.missingByHook` 分别统计 headers、response、assistant 观察缺失；报告保留有细项的请求样本数，旧日志不补零。缺失不能区分宿主不提供钩子与事件遗漏，也不等于网络故障。
- 自动黑匣子保留 `context.projected` 的 inputBytes/outputBytes/budgetBytes、checkpointed、omittedMessages、overBudget 与原因；正常回合只保存有界 contextProjection 计数和最后一次观测，不增加逐事件落盘。报告将投影字节预算与模型 token 窗口区分，超额本身不触发故障通知、自动压缩或重试。
- `/blackbox` 按同一 runtime/capture/session 内已观察到的 toolCallId/parentToolCallId 关联嵌套工具失败链。父子调用都确实有失败结果才关联；重复现场去重，不跨窗口连接，保留各工具原始次数。有限现场可能漏掉关系，链数不代表独立根因数，不改变原问题指纹或业务结果。
- 当用户指令、失败配对等受保护内容已占满投影软预算及检查点预留空间时，保留当前完整视图并明确 overBudget，不再只留下旧失败、删除成功调查和验证。否则已通过的测试会从模型视图消失，诱发重新查历史、查 Git 和重跑测试。历史与身份授权不变；真正 token 窗口压力仍交给现有预算监视器/压缩流程，不新增自动重试或调度。
- 未提供稳定错误码的工具仍显示 `UNKNOWN`，不从任意错误正文猜测根因；正常交接的 `toolUse` 结束仍不冒充任务成功。
- 仅当当前 capture/session/run 内先观察到同一完整 `toolCallId` 的 `workflow.action_rejected`，后续工具结果缺码或同码才只作为已有问题现场，不新增 `UNKNOWN` 故障或累计观察次数；原始 `isError` 等脱敏元数据保留，不修改实际工具结果。不同调用、不同回合及明确不同错误码仍独立计数。关联表仅在内存保留最近 128 个调用（ID 超过 512 字符不关联），新回合、session/branch/项目切换、settled/shutdown、失去信任或记录停用时清空；淘汰或缺失先行拒绝时保守独立记录，不靠工具名或错误正文猜测，无新增存储。

## 按请求观察 Provider 缓存 usage

自动黑匣子另按 `before_provider_request` 与 `provider_stream_event`/assistant 生命周期关联缓存 usage，并在 `message_end` 记录同一请求的归一化 `cacheRead`/`cacheWrite`。单次记录保留 provider/model、当前角色与推理强度、压缩/交接边界、缓存键是否存在，以及选定输入字段的 HMAC 指纹；不落盘原文、请求头或完整 payload。指纹使用进程内随机密钥，不能跨运行比较，也不证明 Provider 实际采用了相同缓存键。

- 原始计数分别区分正数、显式零、缺失、无效/越界；没有 stream usage 观察与明确报告零不是一回事。规范化计数另列，不以其零值覆盖原始状态。
- 只有身份和事件关联可信、观察正常且 assistant 请求结果可用时，才给出原始 read 为零/正数的有限结论；重复/冲突事件、重叠或错位请求、无效/缺失响应 ID、失败、中止、session/角色/model 边界变化、hook 不可用或观测异常都保留未知。关联回退为有序 hook 推断而非宿主请求 ID。
- `transport`、请求形式及扩展不可见的 transport/full-delta 均标为 unavailable；这些诊断只描述扩展实际收到的公开 hook 观察，不能证明最终网络请求、服务端缓存命中/未命中或原因。响应 ID 与选定字段仅保存有界 HMAC 指纹；指纹预算超限时明确不可用。
- 诊断只读；不改请求、缓存策略或 Provider 行为。信任、关闭、队列、轮转和写失败保护沿用黑匣子边界，观测失败不影响模型执行。

## 预算压缩后的角色交接续接

预算压缩可能中断一个已保存的角色交接。仅本次压缩成功且原有待交接 ID、session/context 与角色代次仍有效时，运行时回到既有角色交接调度器；调度器再次检查 branch、目标角色、停止/恢复门、Agent/宿主忙碌状态和排队消息。此路径续接已有授权交接，不创建任务或 attempt。压缩失败、未知结果、用户停止、恢复门或身份变化都不续跑；压缩失败边界不会经 `agent_settled` 工作流提醒绕过。

自动化生命周期测试不等于真实 Pi 宿主、真实 Provider 或网络链路验证；未据此声称缓存命中、性能、费用收益或宿主调度结果。
