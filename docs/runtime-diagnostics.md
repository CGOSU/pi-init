# 运行诊断

pi-init 在受信任项目中默认启用本地运行诊断，帮助查看扩展运行异常。它不会调用模型、修改工作流或自动重试任务。

## 打开诊断

| 命令 | 用途 |
| --- | --- |
| `/blackbox` | 查看最近的诊断摘要 |
| `/blackbox menu` 或 `/pi-init diagnostics` | 打开诊断面板，查看项目与本机记录 |

## 开关

在启动 Pi 前设置 `PI_INIT_HANDOFF_LOG`：

| 设置 | 行为 |
| --- | --- |
| 未设置 | 使用自动黑匣子；可信项目默认启用 |
| `0` | 关闭诊断采集与写入 |
| `1` | 开启旧版逐事件交接日志，写入 `.pi/logs/handoff.jsonl`，记录比自动黑匣子更详细的交接信息 |

修改环境变量后重启 Pi。旧版详细日志见[角色交接诊断日志](handoff-diagnostics.md)。

## 保存内容与位置

自动黑匣子记录回合摘要和 pi-init 可观察到的有限异常，例如工具或 Provider 错误、恢复与交接异常。它不是完整操作记录：不保存提示词、对话正文、源码、工具输入输出、请求正文或 headers。没有记录不代表没有故障；Provider 与缓存数据也只反映 Pi 暴露给扩展的观察，不能证明网络请求或服务端缓存结果。

- 项目记录：`<项目目录>/.pi/diagnostics/runtime.jsonl`
- 本机全局记录：Pi Agent 目录下的 `diagnostics/pi-init/runtime.jsonl`
- 单文件有大小上限并轮转保留一份备份；过期文件在后续读写时清理，不是定时清理。

诊断保存在本机，不会上传。角色、模型等元数据仍可能敏感，分享前请人工检查。

## 导出与清理

- `/blackbox export <project|global> <新文件路径>`：导出所选范围最多最近 256 条脱敏记录。只写入新文件，不覆盖已有文件，也不会上传。
- `/blackbox clear <project|global>`：交互确认后清理所选范围的诊断记录；无法撤销，不会删除会话或工作流文件。

诊断仅覆盖扩展实际观察到的事件；宿主未提供或扩展未观察到的信息不会出现在记录中。
