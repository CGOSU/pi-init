# 运行诊断

pi-init 在受信任项目中默认启用本地运行诊断，帮助查看扩展运行异常。它不会调用模型、修改工作流或自动重试任务。

## 打开诊断

| 命令 | 用途 |
| --- | --- |
| `/blackbox` | 查看当前项目最近的会话诊断摘要及本机全局记录状态 |
| `/blackbox status session [会话键]` | 查看当前会话，或使用当前项目中的诊断会话键查看历史会话 |
| `/blackbox menu` 或 `/pi-init diagnostics` | 打开诊断面板，选择会话、导出、清理或恢复记录 |

## 开关

在启动 Pi 前设置 `PI_INIT_HANDOFF_LOG`：

| 设置 | 行为 |
| --- | --- |
| 未设置 | 使用自动黑匣子；可信项目默认启用 |
| `0` | 关闭诊断采集与写入 |
| `1` | 开启逐事件交接日志，记录比自动黑匣子更详细的交接信息 |

修改环境变量后重启 Pi。详细模式见[角色交接诊断日志](handoff-diagnostics.md)。

## 保存内容与位置

自动黑匣子记录回合摘要和 pi-init 可观察到的有限异常，例如工具或 Provider 错误、恢复与交接异常。它不是完整操作记录：不保存提示词、对话正文、源码、工具输入输出、请求正文或 headers。没有记录不代表没有故障；Provider 与缓存数据也只反映 Pi 暴露给扩展的观察，不能证明网络请求或服务端缓存结果。

以下路径均相对于 Pi SDK 定位的 Agent 目录（默认 `~/.pi/agent`，可用 `PI_CODING_AGENT_DIR` 覆盖）：

| 记录 | 路径 |
| --- | --- |
| 项目黑匣子 | `diagnostics/pi-init/sessions/<projectKey>/<sessionKey>.jsonl` |
| 详细交接日志 | `diagnostics/pi-init/handoff/<projectKey>/<sessionKey>.jsonl` |
| 本机全局最小故障摘要 | `diagnostics/pi-init/runtime.jsonl` |

项目键和会话键与全局摘要使用相同哈希规则，文件名不含原始项目路径或会话 ID。运行时不读写 Pi 原始会话文件。项目内旧日志不会自动读写、迁移或删除，仍可显式传给离线工具。

每个会话诊断最多保留 2 MiB 的当前文件及一份同样大小上限的 `.1` 备份。项目黑匣子和详细交接日志共享 128 个会话文件组名额（正常写入的总日志内容最多 512 MiB，不含全局摘要）。当名额满额时，新建会话诊断会先跨项目自动回收全部现有段文件均已超过 7 天留存期的过期侧车流（以及已空的过期项目目录）；7 天内的活跃或近期流不会被自动删除，回收后仍满额时拒绝新文件组并报告停录，可显式清理后再恢复。项目黑匣子只汇总最近 7 天的文件，项目摘要最多读取最近 16 个文件或 8 MiB，超出时标明结果不完整。

诊断保存在本机，不会上传。角色、模型等元数据仍可能敏感，分享前请人工检查。

需要保存可比较的本地统计时，可用独立的[诊断采集脚本](diagnostics-collection.md)读取明确指定的项目日志和关联 session，生成带来源指纹的 JSON/Markdown 报告；不增加模型回合，也不修改活动任务。

## 有界故障现场与运行身份

故障首次出现时保存前置现场，随后最多收集 16 个事件或当前回合结束即封口。无关回合不会重复保存旧现场；同类故障真正再次发生时保留首次信息、更新累计次数与最新触发，再打开有界后续窗口。文件轮转仍可能让有效历史短于保留天数。

项目与全局记录携带扩展版本、SDK 版本、来源 commit（可用时）、源码指纹、PID 和加载时间；`/blackbox` 也显示当前实例身份。身份在模块加载时捕获，不在每次写入时读取磁盘新 HEAD 冒充已加载代码。指纹表示加载时对有界包文件的观察，不能证明热 reload 的所有模块原子更新；缺少 Git 或指纹时显示不可用，不影响插件运行。

测试使用独立的临时 Pi Agent 目录。`pnpm test` 运行全量，`pnpm test test/runtime-diagnostics.test.js` 可运行定向回归；统一预加载与扩展测试 harness 隔离全局日志，退出只清理测试自己创建的目录，不删除继承的用户目录。

## 恢复停录记录器

诊断存储、轮转或目录锁失败会停用对应记录器。排除存储故障后，可在受信任项目显式执行：

```text
/blackbox resume project
/blackbox resume global
/blackbox resume handoff
```

恢复先等待本进程待写结束，使用与写入、轮转、清理相同的跨进程锁（会话诊断为 `sidecar.lock`，全局摘要为 `runtime.lock`），探测当前会话文件或全局文件，再复核项目、session 和 branch 身份。只恢复所选记录器接收后续新事件；失败期间被丢弃的记录不会补写，不重放日志或任务，也不更改 `PI_INIT_HANDOFF_LOG` 模式。`handoff` 详细记录仅在详细模式启用时可恢复；关闭模式不会被 resume 打开。锁仍忙或文件不可用时保持停录并报告失败。崩溃遗留锁不自动删除/抢占，须人工核对进程及目录后处理。

状态或恢复成功只表示本次检查通过，不构成长期、跨进程健康保证；诊断采集不参与任务执行和恢复授权。

## 导出与清理

- `/blackbox export <范围> <新文件路径>`：在有界的最近文件范围内导出最多 256 条脱敏记录。超出上限会标明；只写入新文件，不覆盖已有文件，不上传。
- `/blackbox clear <范围|expired|sidecars>`：交互确认路径后，只清理该范围的诊断文件及轮转备份。无法撤销，不会删除旧项目日志、Pi 会话或工作流文件。
- 范围：`project` 或 `handoff` 选择当前项目在该类别下的全部会话；`session` 或 `handoff-session` 只选择当前会话；`global` 选择本机全局摘要；仅用于清理的 `expired` 跨项目清除全部超过 7 天的过期侧车段，`sidecars` 跨项目清除全部受管会话侧车以释放全局 128 组名额（保留本机全局摘要）。`/blackbox menu` 也可选择当前项目的历史会话或上述跨项目清理项。

诊断仅覆盖扩展实际观察到的事件；宿主未提供或扩展未观察到的信息不会出现在记录中。
