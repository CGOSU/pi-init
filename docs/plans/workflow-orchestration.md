# Local 工作流交接状态机

## 本次实现范围

`src/workflow-orchestrator.ts` 收敛调度决策、任务派发/排队/启动、重规划派发/排队，以及完成、阻塞、重试、恢复和取消生命周期事件。继续使用 Pi 公开 Extension API、原 session append/branch 存储与现有 schema，不新增执行器、依赖或配置。

- `selectWorkflowScheduleEffect(state)` 只返回启动、派发、提醒或重规划决策，不修改状态。暂停、终态、已派发和边界压缩等待期间不产生执行动作；启动任务继续遵循依赖顺序。
- `transitionWorkflowDispatch(state, event, now)` 是显式时间输入的纯转换，返回新状态与发送效果。身份或阶段不匹配时返回原状态与空效果。
- 消息层先构造任务包，再持久化 `dispatching` 意图，成功后才发送；发送完成仅回报 `queued`，不代表执行开始或任务完成。
- 实际启动仍要求现有消息消费证据；迟到排队事件不能将 `executing` 回退成 `queued`。执行中续跑提醒使用独立事件，沿用原有提醒次数限制。
- 重规划只能从 `pending` 派发一次；同步重入、重复调用与排队记录写入失败后的重复调用均不能重新发送。
- 所有转换检查 workflow、plan、session、recovery、handoff 与对应 task/attempt 或 revision 身份；旧回调不能推进新尝试。

## 生命周期提交

- `transitionWorkflowLifecycle(state, event, now)` 复用现有业务转换，返回待持久化活动状态、当前层业务结果和提交后效果，不执行 IO。完成/阻塞要求匹配的 executing handoff；入口保留 session、branch、角色和 queued 启动证据校验。
- 命令与工具通过同一 `commitLifecycleTransition` 先持久化活动状态，再撤销终态工作流原身份的续跑。写入失败不运行撤销效果、不清除调度标记、不调度后续任务；成功后才处理这些瞬态变化。
- 旧子流程完成或取消返回父层时，父层进入结果审阅，父状态、子层输出/验证/契约及历史通过一次 workflow append 保存；撤销使用事件前身份，不使用 complete/cancel 后递增的 recoveryGeneration。
- 命令与工具统一：新扁平队列 cancel 取消整个当前队列；旧栈中 cancel 取消当前层、cancel-all 终止父子流程，保留历史。取消不回滚副作用，也不保证已运行的工具/进程或宿主压缩停止。已派发或执行中的取消任务记为结果未知，不伪报未执行。

## 目标归属与扁平队列

新目标共用同一工作流和执行器，goals 只表达归属与约束，任务 goalId 只用于关联/展示，不建立父子调度栈。按依赖是否完成、priority 降序、同级原顺序选择下一项；默认 priority=0，分组本身不加急。正在执行的任务不抢占，只在真实完成或正式阻塞后处理插入。

request-goal 记录目标请求，replan 只新增任务并通过 retainTaskIds 确认原有 pending 项仍有效。任务 ID 全局与历史唯一，dependsOn 可引用旧任务。发现原任务失效时，将插入请求转为普通 request-replan；保留新目标意图与原成果，不靠 retry 绕回运行态。普通 replan 可用空 tasks 只保留/撤销任务，最终队列仍须非空；撤销不能留下悬空依赖，审计保留 superseded 原任务。

分组完成依据实际任务验收与验证记录汇总，不能自动宣告根目标成功。分组被重规划移空时显示“无活动任务”而非成功。插入目标完成后重新检查全队列依赖，不自动恢复旧任务或清除阻塞/未知结果。普通重规划若新增替换任务且旧结果未知、没有结构化澄清处置，必须显式 confirmUnknownOutcome 并提供 reason 核对说明；旧未知标记保留在 superseded 审计中，不伪装为成功。没有就绪项时暂停等待处理，不能悄悄卡在 running。

## 历史迁移规则

- 新持久状态为 v7，严格校验目标 ID、父归属非循环、任务归属存在与安全整数优先级；旧版本不得携带新字段。
- v1–v6 记录仍可读取。旧 parentStack、子流程历史和待处理 nested 请求按旧协议兼容收尾，加载时不强制扁平化、不改任务身份/已完成成果、不重放未知副作用。只追加新版本状态，不改原 session entry。
- request-child 与“子流程：…”成为新目标插入的兼容入口；新请求不生成 parentStack、独立 workflowId 或新的协调账本。subworkflowContract/review-child 仅保留旧记录兼容。
- 新目标分组无独立取消执行器；cancel 取消当前共享队列。撤销某个目标须重规划其未完成任务与受影响依赖。旧 cancel/cancel-all 的层级行为只适用于旧栈。

## 故障与恢复

派发意图写入失败则不发送，存储恢复后可安全重试首次派发。消息发送后的结果未知继续采用原有 fail-closed 恢复：不自动重放，任务副作用须核实后显式确认 retry，并签发新 attempt/handoff。持久化意图不是原子外部消息事务，不承诺 exactly-once。

## 协调证据关联补偿

统一 workflow 持久化入口在 append 成功并更新内存后调用 synchronizeWorkflowLink，不再依赖每个生命周期动作分别记得同步 recoveryGeneration。只允许当前内存工作流与当前 session/协调账本一致、已有链接的 workflowId/planVersion 一致且执行代次落后时追加更新；不创建链接、不跨计划或 session 改绑、不倒退未来代次，也不接受或刷新证据。严格链接匹配与来源/契约就绪门保留。

两本账本仍无原子事务：先保存业务结果，再同步证据链接。后者失败不能把已提交完成伪报为未完成；调度前和补充取证前重试安全补偿。补偿仍失败则不派发，恢复存储后只同步关联，不重放完成任务。旧同计划落后绑定可通过正常调度/恢复受限补齐，缺失或真正不匹配的绑定仍需核查。

## 验证范围

`test/workflow-orchestration.test.js` 覆盖重复派发、发送重入、持久化故障、确定性与输入不变性、逐字段身份隔离、启动与排队乱序、压缩/终态调度门、依赖顺序，以及崩溃恢复和新尝试身份。`test/workflow-lifecycle.test.js` 覆盖子流程完成/取消提交失败不提前撤销、提交后原身份撤销、纯转换确定性、逐字段身份隔离、queued 验收门、未知结果重试、命令提交顺序和审阅恢复。现有工作流、压缩、持久化与启动生命周期测试继续作为回归检查。未进行真实 Pi/TUI 交互及真实进程崩溃/磁盘故障实验，故障由测试注入。

## 保留边界

本阶段不是所有状态写入入口的统一重写。规划、重规划应用、证据协调、派发失败阻塞、角色切换与压缩恢复仍使用现有业务转换与持久化入口；workflow 与 coordination 两个账本之间仍无跨记录原子事务，没有新增并行执行、独立验收角色或持久化 outbox。后续若迁移其他入口，应逐类复用事件转换，而不是同时引入第二套业务权威。
