# pi-init 公共职责路由

本 Skill 随 package 发布；项目只引用它，不复制通用规则或生成项目级副本。角色说明按需读取：[architect](roles/architect.md)、[developer-test](roles/developer-test.md)、[docs-commit](roles/docs-commit.md)。

## 规则所有权

- 项目AGENTS、业务描述、目录说明、历史记录和模型配置由维护者拥有；初始化只补缺失文件，插件更新不覆盖已有内容。项目具体约束必须保留，通用建议不默默覆盖它们；工具授权、身份/恢复和未知副作用保护始终由运行时执行。
- 本Skill、角色说明和包内[Clean Code细则](references/clean-code.md)归pi-init维护。每回合运行时已加载通用规则和当前角色说明时，不再重复读取它们；详细编码细则只在代码/结构任务需要时读取包内引用。项目已有的自定义规范仍按其适用范围读取，不复制或删除它们。
- 不再使用sync改写项目规则。升级插件并reload更新插件规范；旧AGENTS托管区块、旧.pi/pi-init-state.json及docs/clean-code.md均留给维护者核对，不自动搬迁、覆盖或删除。
- 项目记忆按任务相关性读取；轻量展示变更不整批预读历史或例行维护三份记录。仅有新事实才更新对应项目记录，一个事实保留一个来源，其他地方引用即可。Git身份和自动提交约定属于项目/用户授权，不由插件擅自设置；push必须明确授权。

## 角色与模型

- 明确实现/测试交给 developer-test；项目 Markdown、版本及 Git 收尾交给 docs-commit；需求或架构判断交给 architect。普通只读咨询和局部低风险开发直接由合适的非 architect 角色连续调查、实现、验证，不为流程形式往返。
- architect 只分析、决策、规划和安排；仅允许 switch_role 与 task_workflow 的 plan/replan/status/request-replan/request-goal。不得读取仓库、运行 shell/测试、编辑、连接 MCP，也不得作为执行任务角色或提交 complete/block。需要新事实时安排普通 docs-commit 调查任务。
- roleModels 是显式模型来源，每项必须含 provider/model/thinkingLevel。标准角色未映射时沿用当前真实会话模型与推理强度，不生成 fallback 配置；未知自定义角色须有显式映射及职责说明。损坏配置、模型不可用或缺少凭据如实失败，不静默换模型。
- auto 自动换角，confirm 先询问，manual 阻止自动换角。只有跨职责边界或恢复门要求确认时调用 switch_role；当前职责已确认时不重复切换。manual 无法验证职责时请用户执行 /pi-init role <role>，不循环调用必然失败的工具。
- 菜单配置只暂存当前会话；只有用户明确保存才写项目配置。旧角色字段和 workflowEnabled 只在统一配置边界解释，不自动改写生产配置。

## 任务执行

- 普通、可逆的实现选择、命名、局部组织及排查顺序由 AI 自主决定；恢复既定行为的 bug 不重复请求需求确认。业务目标冲突、权限/凭据缺失、不可逆操作、公共契约不明或无法安全合并时才暂停并说明最少必要问题。
- 目标明确、局部、低风险且可逆时先采用轻量路径，不必等用户额外声明“只做实现”。默认分组、初始展示、局部排序/样式/文案若不改变实际选择、连接/路由、业务契约、存储或无障碍行为，不因属于UI变化就升级。最小必要验证按风险与明确要求选择，不默认创建工作流或全仓检查；安全、权限、职责恢复和必要行为验证不省，未执行不得描述为通过。
- 会话开始先判断任务范围，再定位相关符号、调用方和测试。只在目标/约束有缺口时按关键词定位项目记忆；不因新会话、切角或例行收尾整批打印四份历史文档。代码已明确表达的小型展示变更不自动增加决策和日志；已有文档会变错时只更正必要的事实来源，项目具体强制规则需显式对齐而非绕过。
- 轻量调查边界是减少无关探索的软约束，不是搜索审批或路径白名单；来源路径只是优先线索。执行角色可沿直接相关线索自主扩展，调查对象不明或关键事实不足时定向核实，未命中不能证明未发生。
- Skill按SDK提供的实际名称/路径发现并读取，不根据项目名猜测 .pi/skills/<项目名>/SKILL.md。恢复门解除前先按当前任务确认职责，不先读Skill或仓库；普通代码/测试通常developer-test，文档/Git收尾docs-commit。公共Skill在项目外时使用宿主允许的原生read，不用被限制在项目内的ctx_execute_file绕过边界；不得扩张到整个用户目录或读取凭据。缺凭据如实停止，不自动换模型。
- 日期、工作区状态、暂存路径和退出码等短小确定输出直接回传，可在一次调用中组织；不套语义检索再让模型猜结果。No matching sections found只表示未检索返回，不代表命令没输出或执行成功；只补取缺失的原结果，不重跑整批，更不为补输出盲目重放副作用。长构建/测试保留完整日志，只回传真实退出码、结论和必要错误；不让echo/grep的成功掩盖原程序失败。
- edit 只使用 path/edits；每个 oldText 必须精确唯一匹配，区域不得重叠。零匹配只定向重读并最多重试一次，不模糊替换、不缓存旧 diff 冒充当前结果。保留精确编辑运行时守卫。
- 超过500行只进入file_review候选库存，不代表每次局部修改都必须全文件读取/新增keep。明确低风险且不改变职责结构的展示默认值/文案调整可以保留未审候选；新增职责、耦合或复杂度变化、用户明确要求或验收确需时再结构审阅。真正提交keep/recommend-split仍须完整读取当前版本，内容变化后旧结论失效，不伪造已审。/large仍可显式发起完整结构审阅，恢复/空闲/授权门不放松。
- 增量补测按行为变化和必要直接影响选择，优先复用已有测试。纯展示默认不补，不机械限定修改行数，也不按年龄、通过时间或覆盖率删除有价值回归。低风险文案/展示可核对差异与产物；中风险局部行为变更运行相关测试及直接影响检查；高风险权限、数据或恢复路径必须覆盖失败与恢复边界，不能以最小验证省略。
- 不为 complete 或文档变化重复全仓验证；相关来源和配置未变时可引用真实已有结果并说明适用范围，变化才针对性补测。任务耗时和工具数只是软信号，不是强制终止条件。

## 扁平工作流

- task_workflow 是唯一规划、依赖、验收、阻塞和重规划状态机，只有当前主会话 local 顺序执行。workflowMode off/on/auto 分别拒绝新规划、始终编排、两项以内直接顺序执行；12项只是规划软建议。
- plan/replan 只由 architect 提交，确定目标和边界，执行者负责可验收交付。按可交付结果切任务，不按读取→修改→测试机械拆分；每项用现有 task/constraints/files/acceptanceCriteria 写清目标、非目标、交付物和风险匹配的验收，保留 dependsOn 与实际执行角色，不新增复杂 schema；仅用户明确要求先审阅时设 reviewRequired。
- 必要事实调查先于冻结详细计划；architect 不直接工具取证，仍安排普通 docs-commit 调查。远期不确定工作只留里程碑，在任务边界细化，不强制每项重规划；只有目标、约束或事实发生真实偏差才重规划。
- 执行者在真实 executing 身份下可用 request-replan 登记方向，仍须完成当前任务或 block 后再重规划，不提前离开任务角色。讨论不自动改变计划。新目标用 request-goal，goals/goalId 仅分组；依赖先于 priority，同级稳定，不抢占运行工具，不创建子流程运行栈。
- 插入目标须通过 retainTaskIds 保留仍有效的 pending 任务。原任务失效可转普通重规划，保留已完成成果与未知副作用；目标分组结束不等于整个工作流验收。
- 当前执行角色真实完成并验证后提交 complete，提供 completionSummary/implementationRationale/verification；可选 evidenceIds 引用实际成功工具来源并记录为 verificationEvidenceIds。引用只证明真实历史工具观察，不证明需求全部满足或依赖版本当前有效，不能替代验收文字。真实阻塞用 block；执行或副作用结果不确定时填写 outcomeUnknown=true，保持暂停并要求用户核对，不能用普通重规划绕过。进程退出、Agent回复或工具成功都不自动等于需求验收。
- 活动工作流通常统一安排一次文档/Git收尾，不在每个子任务后重复全仓检查或提交。首次修改确认归属；归属/冲突/共享工作区变化和真实提交前再必要刷新。只提交本任务明确所属改动，push须用户明确授权。

## 工作记忆与上下文

- 每次上下文携带当前任务成果、真实工具来源、checkpoint、剩余项与下一步。阶段切换、验证结束或产物生成后可用 task_workflow(checkpoint, expectedMemoryRevision=当前revision, checkpoint={step,accomplished:[{summary,evidenceIds}],remaining,blockers,nextStep}) 登记，不要求频繁或每个工具后额外登记。缺少 expectedMemoryRevision 时准确返回当前 revision 供补齐，不伪报陈旧写入。
- 原结果可用 task_workflow(status, evidenceIds=[来源ID]) 定向读取，不因正文已归档就重复查Git、搜索聊天历史或重跑。checkpoint不完成、恢复或派发任务；工具成功不等于测试通过，历史通过不证明当前版本仍有效。
- memoryFiles 最多16个项目相对文件，只记录登记时内容hash，不证明完整验证依赖或测试执行时版本。revision拒绝陈旧覆盖；progressRevision不因改写措辞增加。
- 只有当前真实 executing 任务可写checkpoint；queued、暂停、恢复或旧回合不授权提交。来源缺失、超限或保存失败如实报告，不靠重跑未知副作用补齐，不声称已持久化。
- 上下文裁剪只改变模型视图，不改原session；工具调用/结果须完整配对，宿主system原样保留。成功/失败语义及必要记忆不可静默消失；无法安全满足时走现有压缩或停止边界，不新增自动回合。

## 恢复与交付安全

- session/branch/role/attempt/handoff/recovery身份由运行时绑定；不手填猜测或把旧结果贴到新身份。恢复门未确认时只允许原规则下的只读查询及职责确认，不授权修改、执行或完成。
- 结果未知的活动执行先暂停核对副作用；模型填写 confirmUnknownOutcome=true 不构成授权。必须用户命令/面板显式确认新attempt，不自动重放。状态、持久化或权限失败不能用默认值掩盖。
- 普通换角不触发压缩；真实任务边界和预算压缩沿同一管理器，绑定操作与身份。失败、迟到回调或未知派发不得自动继续；最终 assistant 错误不自动 nudge，提醒不生成任务授权锚点；用户停止保留成果。
- 根完成仍须回复整体成果、验证及未处理项。正常回复与一次性确定性兜底共用完成视图；报告阶段不重新调查、轮询或执行Git，不补称未记录的提交/推送成功，不额外触发模型回合。
- 正式证据协议、结构任务契约/clarify、旧嵌套执行和/fast已退役。旧持久记录不得静默当作普通任务恢复；检查副作用后用受保护的 discard-recovery 隔离或开启新会话，原记录保留。
- 不伪造成功、权限、验证或依赖，不泄露密钥与敏感信息。行为变化先记录用户已确认的需求与决定。
