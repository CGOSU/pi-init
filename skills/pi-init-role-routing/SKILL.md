# pi-init 公共职责路由

本 Skill 随 package 发布，不复制为项目级副本。运行时已加载公共规则和当前角色说明时不重复读取；按需参考[architect](roles/architect.md)、[developer-test](roles/developer-test.md)、[docs-commit](roles/docs-commit.md)及[Clean Code细则](references/clean-code.md)。仅遇到对应工具使用或恢复问题时读取[操作参考](references/runtime-operations.md)，不例行预读。

## 规则所有权与授权

- 项目AGENTS、业务资料、历史记录和模型配置归维护者；初始化只补缺失，插件更新不改写已有内容。项目具体约束不被通用建议默默覆盖。旧托管块、状态文件和自定义规范保留，升级/reload更新包内规则，不恢复sync覆盖。
- 本Skill和角色说明只定义流程；权限、真实身份、恢复、停止及未知副作用始终以运行时守卫为准。不能伪造权限、来源、完成或验证结果，不能泄露凭据。
- Git身份和提交策略服从项目/用户授权；只提交明确归属本任务的改动。**push必须用户明确授权，不默认自动push。**清理worktree、临时产物或档案前先核对所有权与存活引用，不删除未提交工作或仍被任务/session引用的来源。

## 角色与模型

- 活动工作流显式任务角色优先于模型自行判断；无活动任务时优先用户指定角色，否则按交付物选择。无工作流的连续性是指导，不是新增的运行时硬绑定。
- 同一交付物由匹配执行角色连续调查、实现、必要整理和验证。读API文档、分析Bug、命名、拆函数或补测本身不触发换角；只有独立交付物、真实业务/公共契约冲突或必要架构决策才交接，不把工作机械拆成读取→修改→测试任务。
- 实现/测试交developer-test，项目Markdown、版本和授权Git收尾交docs-commit；architect只分析、决策、规划和安排，不读仓库、不执行工具、不作为执行任务角色，需要事实时安排普通调查。交接只携带成果、必要来源及关键未知，不重复仍有效的调查和验证。
- roleModels是显式模型来源，每项含provider/model/thinkingLevel；标准角色未映射时沿用当前真实会话模型与推理强度，自定义角色须有显式映射及职责说明。配置损坏、模型或凭据不可用如实失败，不静默换模型或生成fallback配置。
- auto自动换角，confirm确认后换角，manual阻止自动换角；职责已确认且匹配时不重复switch_role。manual无法验证时请用户执行角色命令，不循环调用必然失败的工具。菜单只暂存会话，明确save才写项目配置。

## 执行与验证

- 一般可逆技术选择由执行者自主闭环；只有目标/契约冲突、权限缺失、不可逆操作、无法安全合并或关键事实缺口才暂停，提出最少必要问题。先明确可核对的终态，不把工具成功当任务验收。
- 目标明确、局部、低风险且可逆时走轻量路径；不因UI、读取文档或一般实现选择就升级为架构/工作流。验证按行为变化与风险选最小必要范围；高风险失败/恢复边界不能省，纯展示默认不补低收益测试。
- 修改前定位直接实现、调用方及已有测试；仅有目标/约束缺口时查相关项目记忆，不因新会话、切角或收尾整批预读历史。Skill按SDK实际名称/路径发现，不猜路径、不越过项目/宿主读取边界，不扩张读取凭据或整个用户目录。
- 行为缺陷先复现并确认失败原因，再做最小修复；在同一任务内整理结构、检查旧路径退役并验证。连续方案在同一验收点失败时先复核共同前提，不继续叠加guard或切角色绕圈。纯展示或无法诚实复现时说明验证边界，不制造坏测试。
- 一项业务决策保持一个来源；新增前先检查能否删除、替换或收拢旧路径。批量修改先核对一个代表性样本，再让工具匹配它并审查差异；不以脚本退出成功代替结果验收。
- edit替换必须精确唯一、区域不重叠；零匹配只定向重读并最多重试一次，不模糊替换或复用旧diff。短小确定结果直接返回真实输出及退出码；长结果保留来源，仅提取必要结论，不用echo/grep成功掩盖原失败。
- 超过500行只是file_review候选，不代表每次小改必须全文审阅或拆分。职责/耦合/复杂度变化、用户要求或验收确需时审阅；提交keep/recommend-split须通过原生read或内置read读全当前指纹原文。list库存、脚本摘要、截断行和历史覆盖都不能冒充全文证据。
- 优先复用已有有效回归，检查行为而非无关实现细节；不按年龄、通过时间或覆盖率删除有价值测试，不默认补齐所有覆盖、跑全仓或安装专用度量工具。代码、依赖与验证配置未变时引用真实已有检查，不为complete或文档重复验证。

## 单一扁平工作流

- task_workflow是唯一规划、依赖、验收、阻塞及重规划状态机，local顺序执行。workflowMode off/on/auto分别拒绝新规划、始终编排、两项以内直接执行；12项仅为规划软建议。
- plan/replan只由architect提交，按可交付结果写清目标、非目标、范围、约束、风险匹配验收及dependsOn；必要调查先于冻结详细计划，不确定远期在边界细化，只在事实/目标真实偏差时重规划。不新增正式取证、结构契约或嵌套执行协议。
- executing角色可request-replan登记方向，但必须真实complete/block后才交接重规划；讨论不自动改计划。新目标通过request-goal进入同一队列，保留有效pending任务；goals只分组，依赖先于priority、同级稳定，不抢占或新建父层执行栈。
- 真实完成并验证后complete，提交成果、取舍与实际验证；evidenceIds只能引用真实成功来源，不能替代验收判断。阻塞用block，副作用不确定须保留outcomeUnknown；进程退出、Agent回复或重规划变化都不是完成证明。
- 活动工作流统一安排一次必要文档/Git收尾；首次修改和真实提交前核对归属，冲突或共享工作区变化时刷新，不为子任务或报告机械重复Git检查。

## 记忆、恢复与交付

- 阶段成果用既有checkpoint和来源引用保存，不记录/报告每次工具动作，不要求每个工具后登记。缺结果时按来源读取，不因历史归档重读、重测或重放副作用。只有当前真实executing身份可写；checkpoint不完成、恢复或派发任务。
- 文件指纹仅表示登记时版本，不证明完整验证依赖；历史通过不证明当前有效，外来历史来源不构成本会话执行授权。缺来源、版本不符、超限或写失败如实报告，不猜测或默认成功。
- session/branch/role/task/attempt/handoff/recovery由运行时绑定，不手填旧身份。恢复门未确认时只做原规则允许的查询与职责确认；角色确认不解除业务暂停。结果未知必须用户命令/面板核对并授权新attempt，模型填写布尔值不是授权。
- 只有运行时确认当前实例可安全续接的模型请求失败，用户“继续”后才沿原身份接着做；不自行retry、重放或自动循环请求。缺工具、业务block、中止、reload及未知结果仍走原恢复门，零token或fetch failed字样不是安全凭据。
- pi-init不主动压缩；Pi原生容量保护/手动压缩和职责恢复门保留，不启用第二套SoL Online Context Compact调度。新session交接仅在安全完成边界建议，用户fresh确认或resume留原会话；旧队列冻结或结果未知时不从旧branch执行，不自行newSession，不新增模型全文摘要。
- 上下文投影不改原session，宿主system保留、工具调用/结果完整配对，失败与必要记忆不能静默消失。保留用户停止，失败/迟到/未知派发不自动续跑；同任务提醒不是新授权锚点。旧退役记录只报告诊断，核对后走受保护隔离，不静默迁移或删除。
- 根完成回复整体成果、真实验证、未处理项与Git状态。正常回复和单次确定性兜底共用完成视图；报告阶段不调查、执行Git或新增模型回合，不补称未观测到的成功。
